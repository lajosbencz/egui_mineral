# Conventions

API shape, naming and component conventions. Rules: [rules.md](rules.md).

- One entry rule: anything that yields a `WidgetResponse` implements `MineralWidget` and is shown with `ui.mineral(w)` on a `MineralUi<K>` (the only `Ui` that has it, handed out by `Runtime::pass`, `Runtime::ui` and every stylekit container); no `show()` returns a bare `Response` or `WidgetResponse`. Leaves implement `MineralWidget` (`sense()` for drag); widgets built from other widgets implement `Composite` (`compose(&mut self, ui, constraints)`), which sizes from the previous pass and lets each child emit its own semantics (`semantics()` returns `None` when parts emit their own nodes or the widget is decorative). Containers, groups and overlays keep `show(..)` returning their own `*Response`. Events go in `type Output` (read from `WidgetResponse::output`), never in widget fields. Per-pass input is `Core::input()`; inside an egui closure, re-wrap with `let rt = ui.rt(); ui.horizontal(|ui| { let ui = &mut rt.ui(ui); .. })`. Through `DerefMut`, `ui.f(ui.g())` loses two-phase borrows: read `ctx`/`i18n` through `rt` (`rt.ctx()`, `rt.i18n()`) and hoist other reads into a `let`. Apps import `egui_mineral_material::prelude::*` (it coexists with `egui::*`; component names avoid egui's root exports: `PushButton`, `CheckButton`, `Radio`, `ValueSlider`, `TextLink`, `MenuStrip`); widget authors add `egui_mineral::kit::prelude::*`. Each stylekit prelude glob-re-exports `egui_mineral::prelude` (what apps name from the core: runtime, bus, routing, widget glue, bound models) and adds its own items; author traits (`Stylekit`, `MineralWidget`, `Composite`) live only in `kit::prelude`. Stylekit plumbing lives in `egui_mineral::kit` ([module map](workspace.md#module-map)); per-pass runtime steps run only in `Runtime`'s `begin_pass`/`end_pass` and `WindowSpec::show`.
- Response contract: `changed` means a bound value changed; when it is set, the `response` (the `Some` one for closable overlays) has `mark_changed()` called, so `response.changed()` and the field agree. Group components own this; widgets build `WidgetResponse::new(response, output).with_changed(..)`, which marks the response. Click-only widgets (PushButton, Fab, ExtendedFab, IconButton, assist/suggestion Chip, menu and FabMenu items) are read with `.clicked()` (taps count), never `changed`; toggles bind a `&mut bool`, flip it and report `changed` (`ToggleButton`, `IconButton::toggle`, `Chip::filter`); ListItem rows report `ListItemOutput::{activated, leading_toggled, trailing_toggled}` (a row click may toggle a control instead). Taps reach only the topmost click-sensing widget of a layer, as egui routes clicks (`InputContext::tap_on`); content of a clickable container does not select its labels. Event fields (`clicked`, `submitted`, `dismissed`) do not mark. Overlays report `dismissed: Option<overlay::Dismiss>` (why they closed without completing).
- App state is the app's own struct, not a store: widgets borrow fields, discrete actions and `bus` results are one message enum folded by one `update`, undoable ones through `undo` (crate docs of `egui_mineral`).
- Apps use stylekit components; raw egui / ecosystem widgets go through the interop pattern ([`examples/showcase-material/src/pages/interop.rs`](../examples/showcase-material/src/pages/interop.rs)), enforced by `raw-egui-widget`.
- Every widget with an agent key offers `agent_key(..)` to override the id-derived one. Components that take an id salt in `new` derive the default key from it, never a fixed string.
- Constructors take what the component cannot render without: id salt first, then the label (accessible name; icon-only components take an icon plus a label), then counts, items and closures in natural order, the bound value (`&mut T`, `&mut Selection<_>`) last; secondary settings are setters. No two swappable same-typed parameters: a second string or number becomes a setter (`SplitButton::menu_label`, `TextLink::url`, `TourStep::supporting`) or a named struct (`CarouselPadding`). Collection builders take one item as `<item>(impl Into<T>)` and many as the plural `<items>(impl IntoIterator<Item = impl Into<T>>)`, which equals chained singular calls (`item`/`items`, `action`/`actions`, `step`/`steps`, `menu`/`menus`, `avatar`/`avatars`). Landmark and group components name themselves through a constructor label where the name is specific (`Tabs`, toolbars, `Menu`) or else `label(impl Into<String>)` over an i18n default (navigation bar, rail and drawer, `SearchBar`, `MenuStrip`, `Stepper`, `Pagination`, `Breadcrumbs`, `TransferList`, `DescriptionList`, `Timeline`, `Carousel`, `ImageList`, `BottomSheet`); collections whose items are not item structs name them with `item_label(Fn(usize) -> String)` (`Carousel`, `ImageList`); group `disabled(bool)` disables every item and sets `state.disabled` on the group node. Items inside collections (`MenuItem`, `Tab`, `NavDestination`, `PaletteCommand`, `IconAction`, `DialogAction`, `ButtonGroupItem`, `TableColumn`, `DescriptionItem`, `RadioOption`) are plain item structs with `new(label)` or `new(icon, label)` (label-only ones convert `From<&str>`/`From<String>`) and optional setters; they carry their own `disabled(bool)`.
- Variants: style variants of one component are `.variant(XVariant)` (`PushButton`, `IconButton`, `Card`, `Tabs`, `TopAppBar`, `ButtonGroup`); kinds with their own setters get a constructor each (`Chip::assist`/`filter`/`input`/`suggestion`); kinds whose valid options differ get their own builder type from that constructor (`Toolbar::docked`/`floating`, `Dialog::full_screen`).
- Invalid option combinations are unrepresentable, not rewritten and reported at runtime: a component-specific enum lacks the unsupported member (`ContainerVariant`, `FabMenuSize`, `FabMenuColors`), a slot is one field (`ButtonIcon`, `RichTooltip::action`/`secondary_action`, `Snackbar::action` taking a `SnackbarAction` that owns its `command`), and options of one kind live only on its type.
- Field errors: `error(impl Into<String>)` sets one, `maybe_error(Option<String>)` forwards an optional one.
- Units are typed: durations are `std::time::Duration` (`Motion::duration`, `input::Debounce`, `Repeat`, `GestureConfig::long_press`), density is `adaptive::Density`, scheme contrast is `color::Contrast`, ranges convert from `RangeInclusive<f64>` (`impl Into<RangeModel>`). Timestamps on the egui input clock stay `f64` seconds. Validated value types (`Contrast`) offer a sanitizing `new` (rule 10) plus `TryFrom`/`FromStr`/`Display`; vocabulary enums with a text form (`SchemeVariant`) offer `Display`/`FromStr` in snake_case.
- Theme: the brightness preference is the runtime's own (`Core::set_preference`, default `System`, which follows `Context::system_theme`), independent of egui's app-wide `Context::set_theme`, so each window keeps its theme (default `GlobalStyle::Egui`: egui's global style and theme stay the app's). `Core::set_global_style(GlobalStyle::Kit)` makes each outermost pass write `Runtime::style` into egui's style of the shown theme (only when it differs) and the preference into `Context::set_theme`, so root tooltips, popups and, through egui's `sync_window_theme`, native window decorations match, also on an OS flip under `System`; nested passes never write, leaving `Kit` restores nothing. `Stylekit::style` receives the resolved `Core::theme`. `Material::new(contrast)` owns the tokens (baseline at that contrast). `Material::apply(ctx, SchemeSpec)` builds both brightnesses from a brightness-independent spec (`SchemeSpec::scheme(Theme)` for one) and remembers it; `Material::set_tokens(ctx, Tokens)` replaces the tokens of `tokens.theme()` only; `Material::set_contrast` regenerates both from the remembered spec so seeds survive. Widgets read `ui.tokens()` (`MaterialExt`). None of the token setters touches the preference.
- Cargo features: `icu` (ICU4X formatting, else `AsciiFormat`), `persist-fs` and `persist-toml` are default in both crates (the stylekit forwards them to the core), and the stylekit also defaults `bundled-icons` (Material Symbols fonts, 3 MB; without it `Material::new` and `Default` are absent and `Material::with_icon_fonts` takes the `IconFonts`, so a missing font is a compile error, never a runtime one). `persist-json` and `persist-toml` enable one codec each (also forwarded); `persist-fs` adds `FsStorage` (native only), which stores encoded strings and needs no codec. Core opt-ins: `platform-pickers`, `platform-clipboard`, `platform-notify` (`platform-native` enables all three; `NativePlatform` implements `PlatformPickers`, `PlatformClipboard` and `PlatformNotifier` only with their own feature, `PlatformService` is their blanket umbrella), `web-save-stream` (Chromium streams `save_file_writer`; implies `platform-pickers`) and `unstable-hotpatch` (Dioxus `subsecond`, native, command line only, never in a manifest or the feature matrix). Stylekit opt-ins: `unstable-catalog` (component provenance), `unstable-spec` (public generated `spec::tokens`/`spec::defaults`), `theme-file` (TOML load and watch, native only). `unstable-*` features are outside the semver guarantee; cargo-semver-checks and the `Public API diff` job skip them. Their third-party errors are boxed behind `#[source] Box<dyn Error + Send + Sync>`, never public types. Code behind a feature stays lint-clean without it: `just clippy` runs every feature alone, the default set and none per crate (cargo-hack, native and wasm32). Tests needing a feature say so in `required-features` of Cargo.toml only, never `#[cfg(feature)]` on a test module; docs.rs builds the explicit `[package.metadata.docs.rs] features` list (never `unstable-hotpatch`) with `--cfg docsrs` for native and wasm32, and `feature(doc_cfg)` renders the feature badges.
- Sizing: spec size families are `.size(Size)` (or a component's own family enum: `FabSize`, `AvatarSize`); any dp size goes through the shared core override `SizeExt` (`preferred_width`, `preferred_height`, `preferred_size`, `width_range`, `height_range`, `constrain`; named apart from `size(..)`), which narrows the `Constraints` handed to `layout`. Components never add their own dp setters: `layout` keeps the token default when unconstrained and honors tight and ranged constraints on `Measure::visual` (exceptions: [divergences](divergences.md)); composites forward the constraints they get in `compose` to the child that fills them. Overlay and container surfaces (`show(..)`, not `MineralWidget`) keep their own extent setters.
- Shared vocabulary: sizes are `Size`, start/end placement is core `layout::Edge`, orientation is core `layout::Axis` (`.axis(..)`), color sets are `*Colors` enums (`.colors(..)`, Compose `*Colors()`), label hiding is `label_visible(bool)`. Single-selection groups return `SelectionResponse`; picker surfaces return `PickerResponse` inline and `PickerModalResponse` as dialogs. Response verbs: `clicked` is an action item pressed (`clicked: Option<usize>`, named slots `<slot>_clicked: bool`), `selected` an option chosen as a value, `activated` the primary action of a data item (table row, list row, carousel item, image tile, tree node). Positions with more than one index are named structs (`MenuPath`, `TreeAction`), never tuples; components with their own events get their own output (`InputChipOutput`).
- Overlays take their open state at show time: `show(ui|ctx, open: &mut bool, ..)`, and every modal surface (scrim, focus trap) is `show_modal(ui|ctx, open, ..)`, also when it has no non-modal form (`Dialog`, `FullScreenDialog`, `CommandPalette`, pickers, sheets); they clear `open` on dismiss and on completing actions (`Dialog` actions). Floating and modal surfaces take `&Rt` (`Runtime<Material>`); in-layout containers, and surfaces with an in-layout part (docked `SideSheet`, `SearchView`, modal `NavigationRail` whose collapsed rail stays in the layout), take `&mut MineralUi`; anchored popups (`Menu`, `Popover`, `HoverCard`, tooltips) take `&Rt` and the anchor `&Response` and keep their open state internally, toggled by the anchor. Other exceptions to `open: &mut bool`: `SnackbarHost` is queue-driven, and `Tour` binds `&mut Option<usize>` whose `Some` step is its open state (`show` overlays the step, `show_modal` adds the mask). Pickers bind their value in `new` (`DatePicker`, `DateRangePicker`, `TimePicker`), `input_mode(DisplayMode)` picks the inline form and the initial modal mode.
- Overlay plumbing: content overlays return core `overlay::OverlayResponse<R>` (popups, sheets, `FloatingPanel`); components with extra outcomes keep their own `*Response` with `response`/`dismissed` fields. Non-modal dismissal goes through `overlay::dismissal` (Escape, outside press, focus return); modal lifecycle and focus return through the crate's `ModalFocus::scope`. Escape bound to a focused widget uses `kit::overlay::consume_escape_from`: egui drops focus on Escape before widgets run. Reading-order geometry uses `Direction::{start_x, span_x, offset_x}` (a part as a reading-order `Rangef`, `Rangef::point` for a point), `Direction::{span_from, from_edge, mirror, reversed, cursor, column, row}` (`RowCursor` lays out row parts from the reading start), `Direction::pick(ltr, rtl)` for directional icons and signs (a back arrow is `ICON_ARROW_FORWARD` in RTL), `Sides { left, right }` for a pair resolved to physical sides, never `if rtl` arithmetic; `TextEdit`s set `.align(Align2([dir.start_align(), Align::Min]))` (`text_field::BareEdit` does), egui otherwise inherits the parent layout's alignment.
- One runtime per native window: `Context` data, `Options` and the global style are shared by every viewport. Ids built from an app salt alone (not from a `Ui` id) go through `kit::scoped_id` (per runtime and window) before keying `Context` data, areas or modals; `egui::Modal` gets an explicit `.frame(..)`, lib `Area`s `.fade_in(!reduced)`.
- Builder naming: `icon`, `trailing_icon`, `supporting` (secondary text), `title`, `headline` (MD3 headline text of a surface or list item), `overline` (text above a list item's headline), `*_label` for extra accessible/display names, `leading`/`trailing` only for slot enums, `*_button(bool)` for an optional built-in button (`back_button`, `menu_button`, `close_button` in a surface title row), `dismissible(bool)` for the close icon of a transient message (`Snackbar`, `Alert`), `*_axis(Axis)` for the orientation of a part (`NavigationBar::item_axis`). Counts and digit counts are `u8` (`fraction_digits`), `NonZeroU8` where zero is invalid (`Rating::count`); family setters take `impl Into<..>` (`Fab::size`, `colors`). Caches keyed on caller data take an explicit version (`DataTable::data_version`). Setter parameters carry the setting's name (`disabled(disabled: bool)`, `agent_key(key)`), never single letters or `on`. Flag setters take a `bool` (`disabled(bool)`, never a bare toggle); no positional bool parameters in public functions, split the function or take an enum (`edit::FieldFocus`, `focus::TabStop`, `widget::Availability`).
- Widget-author helpers, reused instead of re-derived: `SemanticNode::clickable(Availability)` (click/focus actions, `state.disabled`), `SemanticNode::pressable(Availability)` (click only, for parts without focus), `SemanticNode::ranged(NumericRange, Availability)` (range plus Focus/SetValue/Increment/Decrement) with `RangeModel::numeric(value)`, `SemanticNode::editable(Availability)` (Focus/SetValue), `kit::input::accesskit_requested(ctx, id, Action)`, `kit::state::TempState` (`try_load`/`load`/`load_or`/`store` of per-widget temp state) and `kit::state::Memo::get_or_compute` (cache keyed by a hash), `RangeModel::drive` (keys and AccessKit on a range), `motion::spring` (0..1 per flag via `f32::from(bool)`), `Tokens::role(ColorRole)`, `kit::delegate_widget_meta!` (forward `MineralWidget` metadata), `kit::widget_meta!` (`id_salt` from `self.salt`, `enabled` from `self.disabled`, `min_target`/`sense` constants: `salt, enabled, no_target, frame_sense, hover`), `WidgetFrame::{press_pos, drag_pos}`, `OverlayResponse::is_open`. Material crate internals: `parts::press` (`Press { clicked, interaction }`), `button::Surface` (container fill, elevation, outline), `common::{elevated_frame, dim}`, `row_parts::{OptionRow, RowMetrics, drive_list, drive_embedded}` (option lists; keys through core `ComboState`), `text_field::FieldChrome` with `field_chrome_setters!` (field variant, supporting, error, icon), `text_field::BareEdit` (frameless field `TextEdit` over a rect) and `text_field::submitted`, `dialog::PickerModal` (picker modal lifecycle, commit, Dialog node) with `dialog::PickerLabels` and `picker_label_setters!`.
- Every interactive element emits a `SemanticNode` (`semantic::emit`, built only when wanted) with a stable agent key, role, states and actions. Keys derive from the id salt, never from displayed text or `Debug` output: `StableId::of(&salt, "<kind>")` is `<salt key>-<kind>`, `id.sub(..)` a part of node `id`; collection items use `<parent-key>-<item>-<kind>`, where `<item>` is the item's own `salt(..)`, else its command `ActionId`, else its index (`widget::item_salt` in the Material crate, then `StableId::of(&item, "<kind>")`), so inserting items keeps the keys and egui ids of identified ones; collections without item identity use `StableId::of(&salt, (i, "<kind>"))`. Keys built from static text and numbers render only when read, so building them per item allocates nothing; `agent_key(..)` takes `impl Into<StableId>` and parts pass a `StableId`, never a formatted `String`. Nodes carry `StableId`, never a key `String` re-wrapped per pass; helpers take `&KeyedSalt` and build ids inside the `semantic::emit` closure. egui ids never hash agent keys (an `agent_key(..)` override must not change widget identity).
- Id parameters: every public constructor or model that names state takes `id_salt: impl Into<semantic::KeyedSalt>` (never `impl AsIdSalt`, `egui::Id` or `Hash + Debug`); the one exception is the item type of `dnd::reorder_list` and `ReorderableList` (`T: egui::AsIdSalt`), a row identity hash that names no state and never feeds an agent key. `KeyedSalt` pairs the egui salt (hash equal to `IdSalt::new(value)`) with its agent key text from `semantic::KeySalt`, implemented for `&'static str`, `String`, `Cow<'static, str>`, integers, `char`, `bool`, `shortcut::ActionId`, references and tuples up to 4 (parts joined with `-`); normalized static text, numbers and tuples of them do not allocate (`KeySalt::key_parts`). App salt types implement `KeySalt` next to `Hash` and `Debug`; other borrowed text is passed as `String`. Composites keep their `KeyedSalt` and salt children with `salt.child(part)` (key `<parent-key>-<part>`) or `salt.join(&keyed)`; `agent_key(..)` replaces the key, never the hash.
- Components take MD3 spec values (sizes, paddings, opacities, color/shape/type roles) from `egui_mineral_material::spec` instead of literals. `spec::tokens` and `spec::defaults` are `pub(crate)` unless the `unstable-spec` feature is on; the role vocabulary (`ColorRole`, `ShapeRole`, `ShapeScale`, `TypeScale`, `ElevationLevel`, `Typeface`) is always public. `spec/tokens` is not edited by hand: re-pin with `tools/md3_tokens/fetch.sh [sha]`, then `cargo run -p md3_tokens -- generate`; the generator fails on token forms it does not know.
- Every public stylekit component lives in its category module and registers provenance: `meta!(Type, Category, Origin::Md3 | Origin::Md3Expressive | Origin::Other(&[Kit::..]), "<spec url>")` plus an entry in `catalog::CATALOG`; the category module re-exports it and `prelude` lists it. `catalog` is the non-default `unstable-catalog` feature; `Category::title(ctx)` is a `mineral-category-*` message.
- No user-visible literals in library code: messages go through `I18n::tr` with `mineral-*` ids (`mineral-` marks message ids only; internal root id salts and names, not scoped by a widget id, use `mineral::`, and a test checks every `mineral-*` literal against each catalog, both ways, with key parity across locales); stylekits ship the catalogs ([`crates/egui_mineral_material/locales/en-US.ftl`](../crates/egui_mineral_material/locales/en-US.ftl)), the core none; dates, times and numbers go through `I18n::format()`; `MineralWidget::semantics` gets the `&I18n` for its labels. Agent keys never derive from translated text (use `.key()`).
- Shortcuts are `KeyboardShortcut`s registered through `shortcut::bind` (components bind their own; labels come from `shortcut::label`, never free text). App actions shown in collections take an app-owned `shortcut::ActionId`: palette entries via `.command(id, shortcut)`, menu items via `.command(id)` plus `.trailing(shortcut)`; activation fires the action, the app takes it once with `shortcut::take_action`. Mnemonics are explicit `.mnemonic(char)` builders, laid out by `shortcut::mnemonic_job`; widgets expose them via `MineralWidget::access_key`.
- egui built-ins that fight app bindings (zoom, quit, TextEdit Ctrl+H/K/U/W) go through `Policies::readline` (TextEdit keys) and egui `Options` (zoom, quit; app-wide, set by the app); the keys a `TextEdit` owns are listed once in the shortcut registry, guarded by a drift test against a real `TextEdit`.
- Keyboard follows WAI-ARIA APG through core `RovingFocus` (`RovingFocus::on_key`), `Typeahead`, `date::on_key`, `focus::on_grid_key`, `tree::on_key`, `RangeModel::on_key`, `ComboState::on_key` (`ComboKind::{SelectOnly, Editable, Embedded}`); functions that handle a key press are `on_key`, `key` stays the identity of a node, binding or shortcut. Composite groups have one Tab stop: items use `focus::roving_sense` with `focus::TabStop::at(index, focus::tab_stop(..))`, then `update_group`.
- Public implementable traits (`LocaleFormat`, `PlatformPickers`, `PlatformClipboard`, `PlatformNotifier`, `Stylekit`, `Storage`) are not sealed; methods added to them ship with default bodies.
- Public types: `Debug` on all (`egui_mineral::kit::opaque_debug!` where fields are closures, trait objects or borrows); `Clone` on responses, outputs, events and owned values (builders holding `&mut` or `FnMut` stay non-Clone, so do errors that box a cause); fieldless enums derive `Copy, PartialEq, Eq, Hash`; `Default` only for neutral empty state containers (`ComboState`, `Selection`, `Expansion`, `FormState`, caches) and the neutral member of an option enum (`ValidateOn::Blur`, `Availability::Enabled`), never for a design value (sizes, durations, springs, placements with gaps); config structs that track the design system or grow (`Policies`, `Tokens`, `Shape`, `StateLayers`, `Durations`, `TypeSpec`) have a baseline constructor (`Policies::baseline`, `Tokens::baseline`) and no `Default`. `#[non_exhaustive]` on error and event enums, on error structs built by constructors (`ValidationError`), on `ColorScheme` and on config structs that track the design system or grow (`Policies`, `Tokens`, `Shape`, `StateLayers`, `Durations`, `TypeSpec`; new fields are not breaking, fields stay assignable, build from the baseline constructor), on enums that track growing lists (MD3 role enums `ColorRole`, `ShapeRole`, `ShapeScale`, `TypeScale`; `Arg`, `TableCell`, `FieldKind`, `Charset`, `Scale`, `ColorSpace`, `SchemeVariant`, `WindowClass`; the spec ones are set in the `md3_tokens` generator) and on read-only structs the library builds (`*Response`/`*Output`, results such as `filter::Match` or `tags::Split`, input event payloads); values apps build and pass in (`dnd::Reorder`, `tree::TreeMove`, `motion::Release`, `platform::PickedFile`) stay exhaustive; closed vocabularies (`Axis`, `Edge`, `Size`, `ElevationLevel`) and small closed value structs (`Spring`, `Constraints`, `CubicBezier`, ...) stay exhaustive. Builders consumed by `ui.mineral(..)` or `show(..)` carry type-level `#[must_use = ".."]` (setters need none); `*Response` types do not, since callers routinely drop them. Docs: see [rules](rules.md#enforcement).
- Errors: a variant that wraps a cause carries it as `#[source] Box<dyn Error + Send + Sync>` (`PersistError`, `PlatformError`, `I18nError`), so `source()` walks the chain; the message includes the cause for `to_string()` readers. A cause that lacks `Error` is wrapped in a display-only error, never `format!("{e:?}")`.
- Same-typed parameters that can swap silently are grouped into a named struct with public fields (`HoverDelays`, `UndoShortcuts`, `Surroundings`, `Release`, `Eviction`, `Notification`, `ColumnSize`, `ShapeKey`, `Spring`); results with two same-typed parts are structs, not tuples (`SortColumn`, `DateSpan`, `DropIndicator`, `focus::Cell`, `FileType`, `CheckError`). Where the second argument is a count or length of the first (`Paging::set_index(index, len)`, `Spread::items(current, total)`), the order is subject first, bound second.
- State a library owns is private behind accessors named after the value (no `get_`): `FormState`, `FieldState`, `FieldSpec`, `focus::Grid`. An accessor that would clash with its builder (`FieldSpec::required`) takes the `is_`/`_text`/`_kind` form. Public fields stay only on literal-constructed config and plain data without invariants.
- Collection-like models implement the std traits that fit: `FromIterator`, `Extend` and `IntoIterator for &` (`Selection`, `Expansion`, `SemanticTree`), `FromStr` + `Display` where a canonical text form exists (`Route`), `From<char>`/`From<Edge>` style conversions between vocabularies of identical meaning. `egui::Align` is physical and does not convert to the logical `anchor::Align`/`layout::Edge`.
- Public-dependency types appear in signatures only for `egui`, `jiff` (`date`), `accesskit` (`agent`, `semantic`), `serde` (`persist::{Codec, load, save}` bounds), `futures_util` (`bus::BoxFuture`, `Stream for CommandReceiver`) and, in the stylekit, `egui_material_icons` (`MaterialIcon`); the core root re-exports `jiff`, `accesskit`, `serde` and `futures_util`, the stylekit root `MaterialIcon` and `icons`, `layout::flex` re-exports `egui_taffy`. Other dependencies (taffy styles, icu, fluent) stay behind own types; `layout::Flow` takes `egui::Align`. Use egui's own names (`egui::epaint::MarginF32`) instead of aliases.
- Everything is fully implemented: no `todo!`, stubs or runtime "unsupported" errors.
- Composition over inheritance. Reuse egui/taffy facilities before writing new ones (e.g. egui dnd payloads, `egui::Modal`, `ScrollArea::show_viewport`).
- egui 0.37 specifics: `Id::unique` for root ids, `IdSalt`/`AsIdSalt` for internal salts (public ones are `KeyedSalt`), `Panel::*/CentralPanel::show(ui, ..)`, and `eframe::App::ui`.
- Conventional commits (`feat(core): ...`, `fix(material): ...`); they drive versions and the per-crate `CHANGELOG.md`. Pre-1.0: no backward compatibility, no deprecation shims.
