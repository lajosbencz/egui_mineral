# Conventions

API shape, naming and component conventions. Rules: [rules.md](rules.md).

- One entry rule: anything that yields a `WidgetResponse` implements `MineralWidget` and is shown with `ui.mineral(w)` on a `MineralUi<K>` (the only `Ui` that has it, handed out by `Runtime::pass`, `Runtime::ui` and every stylekit container); no `show()` returns a bare `Response` or `WidgetResponse`. Leaves implement `MineralWidget` (`sense()` for drag); widgets built from other widgets implement `Composite` (`compose(&mut self, ui, constraints)`), which sizes from the previous pass and lets each child emit its own semantics (`semantics()` returns `None` when parts emit their own nodes or the widget is decorative). Containers, groups and overlays keep `show(..)` returning their own `*Response`. Events go in `type Output` (read from `WidgetResponse::output`), never in widget fields. Per-pass input is `Core::input()`; the layout methods of `MineralUi` (`horizontal`, `horizontal_centered`, `horizontal_top`, `horizontal_wrapped`, `vertical`, `vertical_centered`, `vertical_centered_justified`, `centered_and_justified`, `scope`, `scope_builder`, `with_layout`, `push_id`, `indent`, `group`, `allocate_ui`, `allocate_ui_with_layout`, `add_enabled_ui`) forward to egui's and hand their closure a `MineralUi`; only egui containers that hand out a plain `Ui` (`Frame::show`, `ScrollArea::show`, panels) re-wrap with `let rt = ui.rt(); frame.show(ui, |ui| { let ui = &mut rt.ui(ui); .. })`. Apps keep the `Arc<Runtime<K>>` in a field and borrow it per pass (`let rt = &self.rt;`), never `Arc::clone` per frame. Through `DerefMut`, `ui.f(ui.g())` loses two-phase borrows: read `ctx`/`i18n` through `rt` (`rt.ctx()`, `rt.i18n()`) and hoist other reads into a `let`. Apps import `egui_mineral_material::prelude::*` (it coexists with `egui::*`; the kit's `Ui` alias is `MaterialUi<'a>`, never `Ui`; component names avoid egui's root exports: `PushButton`, `CheckButton`, `Radio`, `ValueSlider`, `TextLink`, `MenuStrip`); widget authors add `egui_mineral::kit::prelude::*`. Each stylekit prelude glob-re-exports `egui_mineral::prelude` (what apps name from the core: runtime, bus, routing, widget glue, bound models) and adds its own items; author traits (`Stylekit`, `MineralWidget`, `Composite`) live only in `kit::prelude`. Stylekit plumbing lives in `egui_mineral::kit` ([module map](workspace.md#module-map)); per-pass runtime steps run only in `Runtime`'s `begin_pass`/`end_pass` and `WindowSpec::show`.
- Response contract: `changed` means a bound value changed; when it is set, the `response` (the `Some` one for closable overlays) has `mark_changed()` called, so `response.changed()` and the field agree. Group components own this; widgets build `WidgetResponse::new(response, output).with_changed(..)`, which marks the response. Click-only widgets (PushButton, Fab, ExtendedFab, IconButton, assist/suggestion Chip, menu and FabMenu items) are read with `.clicked()` (taps count), never `changed`; toggles bind a `&mut bool`, flip it and report `changed` (`ToggleButton`, `IconButton::toggle`, `Chip::filter`); ListItem rows report `ListItemOutput::{activated, leading_toggled, trailing_toggled}` (a row click may toggle a control instead). Taps reach only the topmost click-sensing widget of a layer, as egui routes clicks (`InputContext::tap_on`); content of a clickable container does not select its labels. Event fields (`clicked`, `submitted`, `dismissed`) do not mark. Overlays report `dismissed: Option<overlay::Dismiss>` (why they closed without completing).
- App state is the app's own struct, not a store: widgets borrow fields, discrete actions and `bus` results are one message enum folded by one `update`, undoable ones through `undo` (crate docs of `egui_mineral`).
- Apps use stylekit components; raw egui / ecosystem widgets go through the interop pattern ([`examples/showcase-material/src/pages/interop.rs`](../examples/showcase-material/src/pages/interop.rs)), enforced by `raw-egui-widget`.
- Every widget with an agent key offers `agent_key(..)` to override the id-derived one. Components that take an id salt in `new` derive the default key from it, never a fixed string.
- Constructors take what the component cannot render without: id salt first, then the label (accessible name; icon-only components take an icon plus a label), then counts, items and closures in natural order, the bound value (`&mut T`, `&mut Selection<_>`) last; secondary settings are setters. No two swappable same-typed parameters: a second string or number becomes a setter (`SplitButton::menu_label`, `TextLink::url`, `TourStep::supporting`) or a named struct (`CarouselPadding`). Collection builders take one item as `<item>(impl Into<T>)` and many as the plural `<items>(impl IntoIterator<Item = impl Into<T>>)`, which equals chained singular calls (`item`/`items`, `action`/`actions`, `step`/`steps`, `menu`/`menus`, `avatar`/`avatars`). Landmark and group components name themselves through a constructor label where the name is specific (`Tabs`, toolbars, `Menu`) or else `label(impl Into<String>)` over an i18n default (navigation bar, rail and drawer, `MenuStrip`, `Stepper`, `Pagination`, `Breadcrumbs`, `TransferList`, `DescriptionList`, `Timeline`, `Carousel`, `ImageList`, `BottomSheet`); collections whose items are not item structs name them with `item_label(Fn(usize) -> String)` (`Carousel`, `ImageList`); group `disabled(bool)` disables every item and sets `state.disabled` on the group node. Items inside collections (`MenuItem`, `Tab`, `NavDestination`, `PaletteCommand`, `IconAction`, `DialogAction`, `ButtonGroupItem`, `TableColumn`, `DescriptionItem`, `RadioOption`) are plain item structs with `new(label)` or `new(icon, label)` (label-only ones convert `From<&str>`/`From<String>`) and optional setters; they carry their own `disabled(bool)`.
- Bindings and keys: a selection component names its binding by constructor: `new(.., &mut K)` binds one value, `optional(.., &mut Option<K>)` none or one, `multi(.., &mut Selection<K>)` many (a component whose only binding is a `Selection` keeps `new`: `TagPicker`, `TagGroup`). Its items carry an app value through `item(value, x)` and `items(pairs)` over value-free item structs (`RadioOption`, `ListOption`, `Swatch`, `Tab`, `OptionGroup::item`), and responses report values, never positions (`SelectionResponse<K>::selected`, `toggled: Option<K>`, `activated: Option<K>`, `ComboboxOutput<K>::selected`). Flows are keyed the same way: `Steps<K>` (default `usize`, `Steps::new(0..n)`) orders app keys and `Stepper::step(key, label)`/`Tour::step(key, step)` label them. Closure-built collections take the key per call (`AccordionUi::item(key, ..)`, Material `AccordionUi::panel(key, ..)` over an `Expansion<K>`, `ListUi::item(key, ..)`). Tables and grids take their rows at show time as `table::Rows<K>` (`show(ui, rows, ..)`: `usize` keys rows by data index, `&[K]`/`&Vec<K>` by slice, `table::RowKeys::new(len, Fn(usize) -> K)` by function), so `Selection<K>` and the response are type-checked against the rows; keys bind selection, activation, row ids and agent keys while cell closures stay indexed by data index (Fluent `Table`, `DataGrid`, Material `DataTable`; `ImageList` and `Carousel` report keys and keep positional ids). Every app value an item, row, card or panel carries is bounded by one trait, `select::ItemKey` (`KeySalt + AsIdSalt + Ord + Clone`, blanket-implemented, in the prelude); uncontrolled per-value state is stored by `egui::Id` of the value, never by `K`, so no `Send + Sync + 'static` bound leaks. App key enums derive `semantic::KeySalt` (`#[derive(KeySalt)]`: kebab-case variant or unit struct name, field keys appended with `-`, `#[key_salt(rename = "..")]`; the derive finds `egui_mineral` through the calling crate's manifest, also via a stylekit re-export); `#[derive(Route)]` composes with it rather than emitting it. Groups without values use `core::convert::Infallible` as `K` (Material `ButtonGroup::new`).
- Variants: style variants of one component are `.variant(XVariant)` (`PushButton`, `IconButton`, `Card`, `Tabs`, `TopAppBar`, `ButtonGroup`); kinds with their own setters get a constructor each (`Chip::assist`/`filter`/`input`/`suggestion`); kinds whose valid options differ get their own builder type from that constructor (`Dialog::full_screen`; kinds sharing no constructor are separate types: `DockedToolbar`, `FloatingToolbar`).
- Invalid option combinations are unrepresentable, not rewritten and reported at runtime: a component-specific enum lacks the unsupported member (`ContainerVariant`, `FabMenuSize`, `FabMenuColors`), a slot is one field (`ButtonIcon`, `Snackbar::action` taking a `TextAction` that owns its `command`), and options of one kind live only on its type.
- Field errors: `error(impl Into<String>)` sets one, `maybe_error(Option<String>)` forwards an optional one.
- Units are typed: durations are `std::time::Duration` (`Motion::duration`, `input::Debounce`, `Repeat`, `GestureConfig::long_press`), density is `adaptive::Density`, scheme contrast is `color::Contrast`, shares of a whole in 0..=1 are `layout::Fraction` (progress values, split ratios, sheet detents, `Fling::dismiss_fraction`; setters take `impl Into<Fraction>`, its constructors saturate; sizes stay `f32` points), ranges convert from `RangeInclusive<f64>` (`impl Into<RangeModel>`); numeric widgets bind any `emath::Numeric` (`NumberField`, `ValueSlider`, Fluent `Slider`, `RangeSlider`, `SpinButton`), working in `f64` with `RangeModel::for_numeric::<N>()` (whole grid for integers) and writing back through `range::to_numeric`, and their `format` closures take `N`. Timestamps on the egui input clock stay `f64` seconds. Keys carry their value type instead of a bare string: `persist::PersistKey<T, C>` (value type and `Codec`) for `persist::{load, save, remove}`, the core's per-viewport `Setting<T>` and per-pass `PassScope<T>` (keyed by `TypeId`), `MineralUi::with_scoped`/`scoped::<T>()` for a kit's `Ui` subtree values (Material density); `UndoCommand::merge` takes `&Self`. Validated value types (`Contrast`) offer a sanitizing `new` (rule 10) plus `TryFrom`/`FromStr`/`Display`; vocabulary enums with a text form (`SchemeVariant`) offer `Display`/`FromStr` in snake_case.
- Theme: the brightness preference is the runtime's own (`Core::set_preference`, default `System`, which follows `Context::system_theme`), independent of egui's app-wide `Context::set_theme`, so each window keeps its theme (default `GlobalStyle::Egui`: egui's global style and theme stay the app's). `Core::set_global_style(GlobalStyle::Kit)` makes each outermost pass write `Runtime::style` into egui's style of the shown theme (only when it differs) and the preference into `Context::set_theme`, so root tooltips, popups and, through egui's `sync_window_theme`, native window decorations match, also on an OS flip under `System`; nested passes never write, leaving `Kit` restores nothing. `Stylekit::style` receives the resolved `Core::theme`. `Material::new()` owns the tokens (baseline at `Contrast::STANDARD`; `with_contrast`, `with_density` and `with_icons` configure it before the runtime takes it). `Material::apply(ctx, SchemeSpec)` builds both brightnesses from a brightness-independent spec (`SchemeSpec::scheme(Theme)` for one) and remembers it; `Material::set_tokens(ctx, Tokens)` replaces the tokens of `tokens.theme()` only; `Material::set_contrast` regenerates both from the remembered spec so seeds survive. Widgets read `ui.tokens()` (`MaterialExt`). None of the token setters touches the preference.
- Cargo features: `icu` (ICU4X formatting, else `AsciiFormat`), `persist-fs` and `persist-toml` are default in both crates (the stylekit forwards them to the core), and the stylekit also defaults `bundled-icons` (its own icon fonts: Material Symbols 3 MB, Fluent UI System Icons 1.6 MB; without it `new` and `Default` are absent and the kit is built with `Material::from_icon_fonts`/`Fluent::from_icon_fonts`, which take the fonts, so a missing font is a compile error, never a runtime one). The Material stylekit also defaults `extras`: the components with `Origin::Other` (the `extras` module, its `prelude` re-exports, `ValueSlider::value_field`), so MD3 purists compile less. Spec code never depends on it: shared building blocks live outside the module; the `behavior` and `spec` test binaries require it (`required-features`). The Fluent stylekit defaults `extras` too: the components beyond Fluent UI React v9 (`SplitPane`, `CommandPalette`, `MenuBar`, `StatusBar`, `Pagination`; `Origin::Other`), with the same rules and test gating. Icons are one mechanism: `egui_mineral::icon::Icon` (two `Glyph`s; an `IconFamily` constant is the one source of a font's glyphs, `IconFamily::glyph`, and of its `IconFont`, `IconFamily::font`), widget parameters take `impl Into<Icon>` (`MaterialIcon` and `FluentIcon` convert), each kit draws its own parts (chevrons, dismiss, check, ...) from its `IconSet` role table (`with_icons(IconSet)` over `from_icon_fonts(fonts)` or `new()` in both kits; runtime setters such as `set_contrast`, `set_density`, `set_contrast_mode`, `set_brand` take the `Context` and repaint, and each has a `with_*` builder for the start value), installed with its `IconFont`s; any font fills any kit's `IconSet`. `From<MaterialIcon> for Icon` lives in the Material stylekit, the core knows no kit. `persist-json` and `persist-toml` enable one codec each (also forwarded); `persist-fs` adds `FsStorage` (native only), which stores encoded strings and needs no codec. Core spawner adapters, opt-in: `spawn-tokio` (native, `spawn::TokioSpawner` over the app's `tokio::runtime::Handle`, a `Spawner` and `BlockingSpawner`) and `spawn-wasm` (wasm32, `spawn::WasmSpawner` over `spawn_local`); each owns the tasks it spawned and cancels them on drop or `shutdown`, the app owns the executor (rules 9 and 11). Core opt-ins: `platform-pickers`, `platform-clipboard`, `platform-notify` (`platform-native` enables all three; `NativePlatform` implements `PlatformPickers`, `PlatformClipboard` and `PlatformNotifier` only with their own feature, `PlatformService` is their blanket umbrella), `web-save-stream` (Chromium streams `save_file_writer`; implies `platform-pickers`) and `unstable-hotpatch` (Dioxus `subsecond`, native, command line only, never in a manifest or the feature matrix). Stylekit opt-ins: `unstable-catalog` (component provenance), `unstable-spec` (public generated `spec::tokens`/`spec::defaults`), `theme-file` (TOML load and watch, native only). `unstable-*` features are outside the semver guarantee; cargo-semver-checks and the `Public API diff` job skip them. Their third-party errors are boxed behind `#[source] Box<dyn Error + Send + Sync>`, never public types. Code behind a feature stays lint-clean without it: `just clippy` runs every feature alone, the default set and none per crate (cargo-hack, native and wasm32). Tests needing a feature say so in `required-features` of Cargo.toml only, never `#[cfg(feature)]` on a test module; docs.rs builds the explicit `[package.metadata.docs.rs] features` list (never `unstable-hotpatch`) with `--cfg docsrs` for native and wasm32, and `feature(doc_cfg)` renders the feature badges.
- Sizing: spec size families are `.size(Size)` (or a component's own family enum: `FabSize`, `AvatarSize`); any dp size goes through the shared core override `SizeExt` (`preferred_width`, `preferred_height`, `preferred_size`, `width_range`, `height_range`, `constrain`; named apart from `size(..)`), which narrows the `Constraints` handed to `layout`. Components never add their own dp setters: `layout` keeps the token default when unconstrained and honors tight and ranged constraints on `Measure::visual` (exceptions: [divergences](divergences.md)); composites forward the constraints they get in `compose` to the child that fills them. Overlay and container surfaces (`show(..)`, not `MineralWidget`) keep their own extent setters.
- Shared vocabulary: sizes are `Size`, a container or track style is `variant(*Variant)` (never a `bool` flag: `ChipVariant`, `ProgressVariant`, `LoadingIndicatorVariant`), a text role is `text_style(TypeScale)` (`<slot>_style` where a widget has two text slots: `AccordionPanel::title_style`), a content scroll area is `scrollable(bool)`, the margin around content is `content_padding(..)`, width bounds are `width(impl Into<Rangef>)` (equal bounds fix it; `SideSheet`, `Card`, `Dialog`, `SearchView`), text buttons of message surfaces are `TextAction`s (`action`/`actions`, a label converts; `RichTooltip`, `Alert`, `Snackbar`, `EmptyPlaceholder`), overflow is `elide(Elide)`, start/end placement is core `layout::Edge`, orientation is core `layout::Axis` (`.axis(..)`), color sets are `*Colors` enums (`.colors(..)`, Compose `*Colors()`), label hiding is `label_visible(bool)`. Selection groups bind item values through core `kit::choice::Choice` (`&mut K`, `&mut Option<K>` or `&mut Selection<K>`; items are added as `item(value, item)`/`items((value, item))`, nothing is selected while the binding matches no item) and return core `select::SelectionResponse<K>`; data types every stylekit shares live in the core and are re-exported by the kits (`status::{StatusItem, StatusTone, StatusProgress}`, `palette::{PaletteCommand, CommandPaletteResponse}`), painting stays in the kit; picker surfaces return `PickerResponse` inline and `PickerModalResponse` as dialogs. Response verbs: `clicked` is an action item pressed (`clicked: Option<A>`, the item's value; named slots `<slot>_clicked: bool`), `selected` an option chosen as a value, `activated` the primary action of a data item (table row, list row, carousel item, image tile, tree node). Positions with more than one index are named structs (`TreeAction`), never tuples; components with their own events get their own output (`InputChipOutput`).
- Overlays take their open state at show time: `show(ui|ctx, open: &mut bool, ..)`, and every modal surface (scrim, focus trap) is `show_modal(ui|ctx, open, ..)`, also when it has no non-modal form (`Dialog`, `FullScreenDialog`, `CommandPalette`, pickers, sheets); they clear `open` on dismiss and on completing actions (`Dialog` actions). Floating and modal surfaces take `&Rt` (`Runtime<Material>`); in-layout containers, and surfaces with an in-layout part (docked `SideSheet`, `SearchView`, modal `NavigationRail` whose collapsed rail stays in the layout), take `&mut MineralUi`; anchored popups take `&Rt` and the anchor `&Response` (or a `Rect`, Material `Menu::show_at`): click-anchored ones (`Menu`, `MenuGrid`, `Popover`, `TeachingPopover`) bind `open` like any overlay, toggled by the anchor. Exceptions to `open: &mut bool`: hover-driven popups (`HoverCard`, tooltips) and gesture-opened context menus (Material `Menu::show_context`) keep their state internally, `SnackbarHost` is queue-driven, and `Tour<K>` binds `&mut Option<K>` whose `Some` step key is its open state (`show` overlays the step, `show_modal` adds the mask). Pickers bind their value in `new` (`DatePicker`, `DateRangePicker`, `TimePicker`), `input_mode(DisplayMode)` picks the inline form and the initial modal mode.
- Overlay plumbing: content overlays return core `overlay::OverlayResponse<R>` (popups, sheets, `FloatingPanel`); components with extra outcomes keep their own `*Response` with `response`/`dismissed` fields. Non-modal dismissal goes through `overlay::dismissal` (Escape, outside press, focus return); modal lifecycle and focus return through the crate's `ModalFocus::scope`. Escape bound to a focused widget uses `kit::layer::consume_escape_from`: egui drops focus on Escape before widgets run. Reading-order geometry uses `Direction::{start_x, span_x, offset_x}` (a part as a reading-order `Rangef`, `Rangef::point` for a point), `Direction::{span_from, from_edge, mirror, reversed, cursor, column, row}` (`RowCursor` lays out row parts from the reading start), `Direction::pick(ltr, rtl)` for directional icons and signs (a back arrow is `ICON_ARROW_FORWARD` in RTL), `Sides { left, right }` for a pair resolved to physical sides, never `if rtl` arithmetic; `TextEdit`s set `.align(Align2([dir.start_align(), Align::Min]))` (`text_field::BareEdit` does), egui otherwise inherits the parent layout's alignment.
- One runtime per native window: `Context` data, `Options` and the global style are shared by every viewport. Ids built from an app salt alone (not from a `Ui` id) go through `kit::scoped_id` (per runtime and window) before keying `Context` data, areas or modals; `egui::Modal` gets an explicit `.frame(..)`, lib `Area`s `.fade_in(!reduced)`.
- Builder naming: `icon`, `trailing_icon(icon, label)` (an icon button, named by `label`), `supporting` (secondary text), `title`, `headline` (MD3 headline text of a surface or list item), `overline` (text above a list item's headline), `*_label` for extra accessible/display names, `leading`/`trailing` only for slot enums, `*_button(bool)` for an optional built-in button (`back_button`, `menu_button`, `close_button` in a surface title row), `dismissible(bool)` for the close icon of a transient message (`Snackbar`, `Alert`), `*_axis(Axis)` for the orientation of a part (`NavigationBar::item_axis`). Counts and digit counts are plain integers (`u8`: `fraction_digits`, `Rating::count`; `usize`: `TextField::rows`) clamped to their valid range through `kit::sanitize` (rule 10), never `NonZero*`; family setters take `impl Into<..>` (`Fab::size`, `colors`). Caches keyed on caller data take an explicit version (`DataTable::data_version`). Setter parameters carry the setting's name (`disabled(disabled: bool)`, `agent_key(key)`), never single letters or `on`. Flag setters take a `bool` (`disabled(bool)`, never a bare toggle); no positional bool parameters in public functions, split the function or take an enum (`edit::FieldFocus`, `focus::TabStop`, `widget::Availability`, `icon::IconStyle`, `kit::rating::Step`).
- Fluent stylekit naming: secondary text has two setter names. `secondary_text` is the secondary text of an item or surface part: the line under its label or title (`Persona`, `Tag`, `MenuGridItem`, `TreeItem`, `TableCellLayout`, `CardHeader`, `Toast`) or the trailing caption of a one-line row (`MenuItem`); `hint` is the help text under a `Field` control. Icon-only slots around text are `icon_before`/`icon_after`, style families `appearance(XAppearance)`, orientation `axis(Axis)`. Controls take `validation(Option<Validation>)`, the value `FieldContext::validation` hands over; `Field` takes `validation(Validation, message)`. Response fields: `dismiss_clicked: bool` is the dismiss button of an in-layout message or tag, `removed: Option<key>` the item a group asks the app to remove, `dismissed: Option<Dismiss>` stays on overlays (`ToasterResponse::dismissed: Option<ToastId>` mirrors `SnackbarHostResponse`). App code names the ui `FluentUi<'_>` (`MineralUi<'_, Fluent>`). List options carry an app value `ListOption<K = String>` (also `OptionGroup`, `ListEntry`), so `Dropdown`, `Combobox`, `TagPicker` bind `Selection<K>` and `Select`, `SwatchPicker` an `Option<K>` of the app's type; `Swatch` and `Tag` carry no value (a swatch is paired with its value, a tag is salted by its `id_salt`). Fluent `ALL` lists are `pub const ALL: &'static [Self]`; its option, slot and token enums, `IconSet`, `FieldContext`, `Shadow` and `ShadowLayer` are `#[non_exhaustive]` (the generated ones are set in the `fluent_tokens` generator), `BrandRamp` is built with `BrandRamp::new`, `IconSet` from `IconSet::fluent()` by assigning fields, and `FluentExt` is sealed.
- Widget-author helpers, reused instead of re-derived: `SemanticNode::clickable(Availability)` (click/focus actions, `state.disabled`), `SemanticNode::pressable(Availability)` (click only, for parts without focus), `SemanticNode::ranged(NumericRange, Availability)` (range plus Focus/SetValue/Increment/Decrement) with `RangeModel::numeric(value)`, `SemanticNode::editable(Availability)` (Focus/SetValue), `kit::interact::accesskit_requested(ctx, id, Action)`, `kit::state::TempState` (`try_load`/`load`/`load_or`/`store` of per-widget temp state) and `kit::state::Memo::get_or_compute` (cache keyed by a hash), `RangeModel::drive` (keys and AccessKit on a range), `motion::spring` (0..1 per flag via `f32::from(bool)`), `Tokens::role(ColorRole)`, `kit::delegate_widget_meta!` (forward `MineralWidget` metadata), `kit::widget_meta!` (`id_salt` from `self.salt`, `enabled` from `self.disabled`, `min_target`/`sense` constants: `salt, enabled, no_target, frame_sense, hover`), `WidgetFrame::{press_pos, drag_pos}`, `OverlayResponse::is_open`. Material crate internals: `parts::press` (`Press { clicked, interaction }`), `button::Surface` (container fill, elevation, outline), `common::{elevated_frame, dim}`, `row_parts::{OptionRow, RowMetrics, drive_list, drive_embedded}` (option lists; keys through core `ComboState`), `text_field::FieldChrome` with `field_chrome_setters!` (field variant, supporting, error, icon), `text_field::BareEdit` (frameless field `TextEdit` over a rect) and `text_field::submitted`, `dialog::PickerModal` (picker modal lifecycle, commit, Dialog node) with `dialog::PickerLabels` and `picker_label_setters!`.
- Every interactive element emits a `SemanticNode` (`semantic::emit`, built only when wanted) with a stable agent key, role, states and actions. Keys derive from the id salt, never from displayed text or `Debug` output: `StableId::of(&salt, "<kind>")` is `<salt key>-<kind>`, `id.sub(..)` a part of node `id`; collection items use `<parent-key>-<item>-<kind>`, where `<item>` is the item's own `salt(..)`, else its app value (`ItemKey`: options, tabs, segments, destinations, swatches, tags, accordion panels, rows), else its command `ActionId`, else its index (`widget::item_salt(.., fallback)` in the Material crate, then `StableId::of(&item, "<kind>")`), so inserting or reordering items keeps the keys and egui ids of identified ones; only collections whose position is the meaning (steps, pages, menus of a bar, action rows) use `StableId::of(&salt, (i, "<kind>"))`. Keys built from static text and numbers render only when read, so building them per item allocates nothing; `agent_key(..)` takes `impl Into<StableId>` and parts pass a `StableId`, never a formatted `String`. Nodes carry `StableId`, never a key `String` re-wrapped per pass; helpers take `&KeyedSalt` and build ids inside the `semantic::emit` closure. egui ids never hash agent keys (an `agent_key(..)` override must not change widget identity).
- Semantic nesting follows egui's widget hierarchy: a node's parent is the nearest node up its `WidgetRect::parent_id` chain. A container emits with the id of the `Ui` holding its children (`ui.unique_id()`, a `scope`/`allocate_ui` response, `layer_id.id` of an area), never a bare persistent id or a `Frame` response, which have no `WidgetRect` above the children. Parts a widget interacts beside itself nest under it automatically inside `MineralWidget::update`, elsewhere under `kit::nodes::parts`; popups nest under `Popup::owner` (the trigger by default); nodes without a widget use `semantic::emit_in(ui, ..)`. `depth` is computed, never set; tree items carry `state.level`.
- Id parameters: every public constructor or model that names state takes `id_salt: impl Into<semantic::KeyedSalt>` (never `impl AsIdSalt`, `egui::Id` or `Hash + Debug`); the one exception is the item type of `dnd::reorder_list` and `ReorderableList` (`T: egui::AsIdSalt`), a row identity hash that names no state and never feeds an agent key. `KeyedSalt` pairs the egui salt (hash equal to `IdSalt::new(value)`) with its agent key text from `semantic::KeySalt`, implemented for `&'static str`, `String`, `Cow<'static, str>`, integers, `char`, `bool`, `shortcut::ActionId`, references and tuples up to 4 (parts joined with `-`); normalized static text, numbers and tuples of them do not allocate (`KeySalt::key_parts`). App salt types implement `KeySalt` next to `Hash` and `Debug`; other borrowed text is passed as `String`. Composites keep their `KeyedSalt` and salt children with `salt.child(part)` (key `<parent-key>-<part>`) or `salt.join(&keyed)`; `agent_key(..)` replaces the key, never the hash.
- Components take MD3 spec values (sizes, paddings, opacities, color/shape/type roles) from `egui_mineral_material::spec` instead of literals. `spec::tokens` and `spec::defaults` are `pub(crate)` unless the `unstable-spec` feature is on; the role vocabulary (`ColorRole`, `ShapeRole`, `ShapeScale`, `TypeScale`, `ElevationLevel`, `Typeface`) is always public. `spec/tokens` is not edited by hand: re-pin with `tools/md3_tokens/fetch.sh [sha]`, then `cargo run -p md3_tokens -- generate`; the generator fails on token forms it does not know.
- Every public stylekit component lives in its category module and registers provenance: `meta!(Type, Category, Origin::Md3 | Origin::Md3Expressive | Origin::Other(&[Kit::..]), "<spec url>")` plus an entry in `catalog::CATALOG`; the category module re-exports it and `prelude` lists it. `catalog` is the non-default `unstable-catalog` feature; `Category::title(ctx)` is a `mineral-category-*` message.
- No user-visible literals in library code: messages go through `I18n::tr` (`kit::{tr, tr_or}`) with typed ids. `i18n::messages!(pub(crate) mod msg = "locales/en-US.ftl", prefix = "mineral-", inherit = egui_mineral::core_messages)` reads the source catalog at compile time: a message without arguments is a const (`msg::CLOSE`), one with arguments a struct with a field per `$variable` (`msg::RangeValue { start, end }`), `msg::CATALOG` the registered catalog, tagged by the file name. No API takes a message id as a string: an id or argument the catalog lacks does not compile, a catalog message no code uses fails `dead_code`, and `inherit` fails the build when the catalog lacks a core message or passes it an unknown argument. Ids carry the `mineral-` prefix (message ids only; internal root id salts and names, not scoped by a widget id, use `mineral::`). Stylekits ship the catalogs ([`crates/egui_mineral_material/locales/en-US.ftl`](../crates/egui_mineral_material/locales/en-US.ftl)), the core only the id and argument schema of its own messages ([`crates/egui_mineral/src/i18n/core.ftl`](../crates/egui_mineral/src/i18n/core.ftl), exported as `core_messages`). Only `en-US.ftl` defines the id set: other locales may lack messages (runtime fallback to the source) but a test fails on ids the source lacks. Apps invoke the same macro on their own catalog ([`examples/showcase-fluent`](../examples/showcase-fluent/src/main.rs)); ids known only at runtime go through `Localizer::message`. Dates, times and numbers go through `I18n::format()`; `MineralWidget::semantics` gets the `&I18n` for its labels. Agent keys never derive from translated text (use `.key()`).
- Shortcuts are `KeyboardShortcut`s registered through `shortcut::bind` (components bind their own; labels come from `shortcut::label`, never free text). App actions shown in collections take an app-owned `shortcut::ActionId`: palette entries via `.command(id, shortcut)`, menu items via `.command(id)` plus `.trailing(shortcut)`; activation fires the action, the app takes it once with `shortcut::take_action`. Typed actions: an action collection pairs each action with an app value, `action(value, spec)`/`actions((value, spec))` (`item(value, spec)` for menu rows and crumbs, `trailing_action` for end status items), the value being any `select::ItemKey` (an app enum deriving `KeySalt`; values may repeat) that also salts the item's id and agent key unless the item has its own `salt(..)` or `.command(..)` id; the response reports the run item as `clicked: Option<A>`, so apps `match` their enums, never strings, positions or parallel `Vec`s. A collection where having no action is valid starts as `X<A = action::NoAction>` (uninhabited) and takes the type of its first value through `action::Widen`, so one collection never mixes value types (`DockedToolbar`, `Menu`, `Dialog`, `StatusBar`, `CommandPalette`); one made only of actions infers `A` from its items (`ButtonGroup`, `FabMenu`, `Breadcrumbs`). Spec types (`IconAction`, `TextAction`, `MenuItem`, `DialogAction`, `PaletteCommand`, `StatusItem`) carry no value. `shortcut::ActionId` stays the identity of shortcut-bound commands only (`shortcut::bind`, `.command(..)`): it is hashed by the registry, named in conflict reports and salts agent keys; apps hold it in a `const` and drain it with `take_action(&ID)`. Responses are plain `#[non_exhaustive]` structs whose fields are all `pub` (no accessor-only private fields, `clippy::partial_pub_fields` is never expected): per-item values of a collection are one `pub` field of the core type `action::ItemResponses<A, T>` keyed by item value (`get(&A)`, `iter()`, `len()`; kits fill it with `push(value, t)`), in both kits (`TopAppBarResponse::actions`, `ToolbarResponse::actions`, `TreeViewResponse::rows`, `ReorderableListResponse::rows`). Containers that run a closure return `*Response<R>` with `response` and `inner`, never `egui::InnerResponse` or a tuple (`layout::ChildResponse`, `dnd::DragSourceResponse`, `ListItemResponse`, `SkeletonResponse`, `MessageBarGroupResponse`); selections bind app keys (`Selection<K>`: Fluent `TagGroup::tag(key, ..)`, list options), never display text. Ids that two code sites must agree on derive from one private helper (`fn edit_id(base: Id) -> Id`), never a literal repeated at each site. A `.command(..)` item fires its command instead and reports no value. Mnemonics are explicit `.mnemonic(char)` builders, laid out by `shortcut::mnemonic_job`; widgets expose them via `MineralWidget::access_key`.
- egui built-ins that fight app bindings (zoom, quit, TextEdit Ctrl+H/K/U/W) go through `Policies::readline` (TextEdit keys) and egui `Options` (zoom, quit; app-wide, set by the app); the keys a `TextEdit` owns are listed once in the shortcut registry, guarded by a drift test against a real `TextEdit`.
- Keyboard follows WAI-ARIA APG through core `RovingFocus` (`RovingFocus::on_key`), `Typeahead`, `date::on_key`, `focus::on_grid_key`, `tree::on_key`, `RangeModel::on_key`, `ComboState::on_key` (`ComboKind::{SelectOnly, Editable, Embedded}`); functions that handle a key press are `on_key`, `key` stays the identity of a node, binding or shortcut. Composite groups have one Tab stop: items use `focus::roving_sense` with `focus::TabStop::at(index, focus::tab_stop(..))`, then `update_group`.
- Public implementable traits (`LocaleFormat`, `PlatformPickers`, `PlatformClipboard`, `PlatformNotifier`, `Stylekit`, `Storage`) are not sealed; methods added to them later ship with default bodies; core-drawn chrome asks the kit for a glyph by a `#[non_exhaustive]` part enum (`Stylekit::chrome_icon(ChromeIcon)`, default `None` for the core's vector form), so new chrome adds a variant, never a trait method. Extension traits (`SizeExt`, `SpawnerExt`) and umbrella traits (`PlatformService`) are sealed: a blanket impl is their only impl, or a private `Sealed` supertrait (`kit::sanitize::Number`) where there is none. Two shapes are permanent by design: `TreeData::children` returns a slice, and `PlatformService` stays the three capabilities it has (a later one is its own trait).
- Public types: `Debug` on all (`egui_mineral::kit::opaque_debug!` where fields are closures, trait objects or borrows); `Clone` on responses, outputs, events and owned values (builders holding `&mut` or `FnMut` stay non-Clone, so do errors that box a cause); fieldless enums derive `Copy, PartialEq, Eq, Hash`; `Default` only for neutral empty state containers (`ComboState`, `Selection`, `Expansion`, `FormState`, caches) and the neutral member of an option enum (`ValidateOn::Blur`, `Availability::Enabled`), never for a design value (sizes, durations, springs, placements with gaps); config structs that track the design system or grow (`Policies`, `Tokens`, `Shape`, `StateLayers`, `Durations`, `TypeSpec`) have a baseline constructor (`Policies::baseline`, `Tokens::baseline`) and no `Default`. `#[non_exhaustive]` on error and event enums, on error structs built by constructors (`ValidationError`), on `ColorScheme` and on every growth-prone enum or struct: spec-tracking options and role lists (MD3 role enums `ColorRole`, `ShapeRole`, `ShapeScale`, `TypeScale`; `Arg`, `TableCell`, `Charset`, `Scale`, `ColorSpace`, `SchemeVariant`, `WindowClass`, `shortcut::Scope`, `shortcut::Trigger`, `IconStyle`, `StatusTone`, `StatusProgress`; the spec ones are set in the `md3_tokens` generator), slot payloads (`ComboItem` and its struct variants, `PageItem`, `kit::command_palette::Row`, `StatusLead`), configs (`Policies`, `Tokens`, `Shape`, `StateLayers`, `Durations`, `TypeSpec`, `GestureConfig`, `PullConfig`, `TargetPolicy`, `Cursors`; new fields are not breaking, fields stay assignable, build from the baseline constructor or `new` plus setters) and library-built values (`*Response`/`*Output`, `Interaction`, results such as `filter::Match` or `tags::Split`, input event payloads, kit temp state such as `kit::menubar::BarState`). Values apps or kits build get a constructor or a `Default`-based builder with private or assignable fields, never a struct literal (`Notification::new`, `ComboList::new(..).selected(..)`, `PullInput::new(now).at_edge(..)`, `Surroundings::new`, `OverflowItem::new(..).priority(..)`, `PickedFile::new`, `SaveRequest::new(..).filter(..)`, `Catalog::new`, `kit::strip::Item::new`); a request with more than one option is one such struct, not positional arguments (`SaveRequest`). No target-dependent public fields: accessors exist on every target and return `None` where the platform has no value (`PickedFile::path`). Core `ALL` lists are `pub const ALL: &'static [Self]`, never a sized array. Only small closed value structs whose fields are their whole meaning (`Spring`, `Constraints`, `CubicBezier`, `dnd::Reorder`, `tree::TreeMove`, `motion::Release`, ...) and the geometry vocabularies (`Axis`, `Edge`) stay exhaustive. Builders consumed by `ui.mineral(..)` or `show(..)` carry type-level `#[must_use = ".."]` (setters need none); `*Response` types do not, since callers routinely drop them. Docs: see [rules](rules.md#enforcement).
- Errors: a variant that wraps a cause carries it as `#[source] Box<dyn Error + Send + Sync>` (`PersistError`, `PlatformError`, `I18nError`), so `source()` walks the chain; the message includes the cause for `to_string()` readers. A cause that lacks `Error` is wrapped in a display-only error, never `format!("{e:?}")`.
- Same-typed parameters that can swap silently are grouped into a named struct with public fields (`HoverDelays`, `UndoShortcuts`, `Surroundings`, `Release`, `Eviction`, `Notification`, `ColumnSize`, `ShapeKey`, `Spring`); results with two same-typed parts are structs, not tuples (`SortColumn`, `DateSpan`, `DropIndicator`, `focus::Cell`, `FileType`, `CheckError`). Where the second argument is a count or length of the first (`Paging::set_index(index, len)`, `Spread::items(current, total)`), the order is subject first, bound second.
- State a library owns is private behind accessors named after the value (no `get_`): `FormState`, `FieldState`, `FieldSpec`, `focus::Grid`. An accessor that would clash with its builder (`FieldSpec::required`) takes the `is_`/`_text`/`_count` form. Public fields stay only on literal-constructed config and plain data without invariants.
- Forms bind the app's value: `Form::new(id_salt, &mut FormState, &mut T)`, each field binds a `&mut V` part of `T` through the kit's `FormUiExt` (`text`, `check`, `select` over `Option<K>`, `multi_select` over `Selection<K>`, `date`, `number` over any `Numeric`) with typed `form::Validator<V>`s (`NumberRange` over numbers), cross-field rules are `Form::rule(Fn(&T))`; `FormState` holds only meta state (dirty, touched, errors, submission) keyed by field salt (`field`, `field_mut`), a submit reports `FormResponse::submitted: bool` with the values already in `T`, and `finish_submit(Result<(), Vec<CheckError>>)` shows server errors on their fields. No string-keyed value maps.
- Collection-like models implement the std traits that fit: `FromIterator`, `Extend` and `IntoIterator for &` (`Selection`, `Expansion`, `SemanticTree`), `FromStr` + `Display` where a canonical text form exists (`Route`), `From<char>`/`From<Edge>` style conversions between vocabularies of identical meaning. `egui::Align` is physical and does not convert to the logical `anchor::Align`/`layout::Edge`.
- Public-dependency types appear in signatures only for `egui`, `jiff` (`date`), `accesskit` (`agent`, `semantic`), `serde` (`persist::{Codec, load, save}` bounds), `futures_util` (`bus::BoxFuture`, `Stream for CommandReceiver`); the core root re-exports `jiff`, `accesskit`, `serde` and `futures_util`, the Material stylekit owns `MaterialIcon` (`icons` is generated by `tools/material_symbols`, `just spec`) and keeps `egui_material_icons` private for the font bytes, `layout::flex` re-exports `egui_taffy`. Other dependencies (taffy styles, icu, fluent) stay behind own types; `layout::Flow` takes `egui::Align`. Use egui's own names (`egui::epaint::MarginF32`) instead of aliases.
- Everything is fully implemented: no `todo!`, stubs or runtime "unsupported" errors.
- Composition over inheritance. Reuse egui/taffy facilities before writing new ones (e.g. egui dnd payloads, `egui::Modal`, `ScrollArea::show_viewport`).
- egui 0.37 specifics: `Id::unique` for root ids, `IdSalt`/`AsIdSalt` for internal salts (public ones are `KeyedSalt`), `Panel::*/CentralPanel::show(ui, ..)`, and `eframe::App::ui`.
- Conventional commits (`feat(core): ...`, `fix(material): ...`); they drive versions and the per-crate `CHANGELOG.md`. Pre-1.0: no backward compatibility, no deprecation shims.
