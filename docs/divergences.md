# Divergences

Deliberate departures from the MD3 spec, Compose behavior or our own [conventions](conventions.md).

| Area | Divergence | Reason |
|---|---|---|
| Sizing of `CheckButton`, `RadioButton`, `Switch` | Never measure below the control (box, icon, 52x32dp track), against the [sizing convention](conventions.md) that `layout` honors tight constraints. A narrower row overflows. | The spec sizes do not shrink, a squeezed control would paint over its neighbours. |
| `SegmentedButton::equal_width(false)` | Segments size to their content instead of the widest one (Compose `weight(1f)`). Opt-in, equal is the default. | Dense toolbars: equal widths waste room beside short labels. |
| Density | `adaptive::Density` (`Material::set_density`, `MaterialUiExt::with_density` per subtree) applies to every component, container and hit target alike, and `Density::MIN` is -6 (4dp per step, -24dp). Hit targets: `Stylekit::min_target` shrinks every resolved minimum target (`MinTarget::Auto` and the 48dp `adaptive::MIN_INTERACTIVE`) 4dp per step, never below the visual box; slots a component reserves itself use `adaptive::min_interactive(density)`, invisible resize edges keep 8dp. `MineralUi::target` is the only public resolution of a `MinTarget`, so no kit code reads an unadjusted one. Containers shrink 4dp per step down to their content (glyph or text lines plus padding) instead of a fixed floor: buttons at the default size (`PushButton`, `ToggleButton`, `IconButton` and `SplitButton` at `Size::Small`, `ButtonGroup`), segmented buttons, chips, control state layers, sliders (handle, down to the track), text fields and everything built on them (select, combobox, date, number, tag and OTP fields, search bar and view), list rows (list, menu, accordion, setting row, stepper, transfer list, tree, data table, command palette), tabs, toolbars, top app bar (action row), navigation bar, rail and drawer items, pagination, `MenuStrip`, `StatusBar`. `TreeView` paddings (MD3 list: 16dp) and its default indent also narrow 4dp per step, to 4dp. Fixed (targets still shrink, parts inside follow their own rule): explicit `Size` families other than the default (a prominence choice); `Fab`, `ExtendedFab`, `FabMenu` (prominence); `Dialog`, `FullScreenDialog`, sheets and their drag handle, `FloatingPanel`, `Popover`, tooltips, `Tour` (surfaces sized by content or spec); `DatePicker`, `DateRangePicker`, `TimePicker` (spec-fixed 360dp container, 48dp day grid and 256dp dial; a dense grid is open in [todo](todo.md)); `Snackbar`, `Alert` (message surfaces); `Badge`, progress and loading indicators, `Skeleton`, `Avatar`, `Rating` glyphs, dividers (size is the signal); `Card`, `Carousel`, `ImageList`, `FileDrop`, `SplitPane` (content containers). | Hit targets are the app designer's choice through density; dense desktop inspectors need 28-32dp rows whose controls fit them. Compose density stops at -3, `minimumInteractiveComponentSize` ignores it and MD3 list paddings and toolbars have none. |
| `SideSheet::initial_width` | The width before a user resize is app-chosen within `width(bounds)`; default the MD3 360dp. | Docked sheets as side columns of a desktop layout. |
| `OtpField` label and affixes | The label shows above the cells (`BodySmall`, the floated text field label size) unless `label_visible(false)`, which keeps it as the accessible name. No `prefix` or `suffix`. | OTP is not an MD3 or Compose component; Compose affixes belong to a text field's single text run and the cells hold one character each, so there is no run to attach them to. |
| `Accordion` flat variant | `AccordionVariant::Flat` drops the container, outline, shape and header start padding: a plain section header (title, chevron without the trailing well) with a divider under it, body unpadded; keys, semantics and Up/Down roving are the card's. | Dense inspector property groups; the MD3 Expressive expanded list is a card. |
| `SegmentedButton` press | No z-index raise on press, segments paint in row order. | egui paints in call order. |
| `SegmentedButton` check | The check's scale spring keeps running while hidden, a quick reselect starts part-way. | One spring per segment. |
| `SegmentedButton` overflow | A row wider than the available width shrinks its segments evenly and clips their labels. | Compose has no defined overflow. |
| `SideSheet::resizable` | Standard and modal sheets get a drag handle on the inner edge (arrow, Page, Home and End keys, Splitter semantics) within `width(bounds)`, the width persisting per sheet id. | MD3 side sheets have a fixed width; desktop inspectors need user-sized panels. |
| Material `Toolbar::custom` | A content slot between icon actions, measured at its natural width the pass before it is laid out (first pass discarded); a docked toolbar with custom items packs from the start instead of `SpaceBetween` and hides trailing custom items that do not fit, vertical floating toolbars hide them; only a focusable returned response joins the arrow-key roving order, a self-roving group (`SegmentedButton`) is entered by Tab. | Compose toolbars take only icon content; apps need inline controls at the toolbar height. |
| Material `TreeView::unfocused_selection_color` | Selected rows take another container role while focus is outside the tree. Opt-in; by default selection keeps `ITEM_SELECTED_CONTAINER_COLOR`. | Desktop trees show which selection the keyboard acts on; MD3 lists have one selected state. |
| `MineralWidget::Kit` | A widget names one stylekit type, and app code is typed by it (`MineralUi<'_, Material>`, `Rt`); there are no theme-agnostic widgets or `dyn Stylekit` passes. | Kit-typed tokens and extension traits (`MaterialExt`, `FluentExt`) resolve statically, with no downcast or shared token vocabulary. Cost: widgets usable under any kit would need a breaking change. |
| `StatusItem::tone` | `StatusTone` has `Default` and `Error` only, no warning tone; apps pass their own through `StatusItem::colors`. | MD3 defines no warning color role, none is invented. |
| Fluent fonts | egui default fonts replace Segoe UI and Bahnschrift; semibold uses an app-installed face (`install_semibold`) or the regular one. | Segoe UI is not redistributable. |
| Fluent high contrast | `Scheme::HighContrast` paints the `createHighContrastTheme` colors; CSS forced-colors system colors are not read. | egui has no forced-colors media query. |
| Fluent shadows | CSS `box-shadow` blur maps to `egui::Shadow::blur` one to one, the two layers (ambient, key) paint as two shadows. | egui blur is not a Gaussian sigma. |
| Fluent policies | Mouse target 24 (split button minimum), touch target 48, core breakpoints. | Fluent web sets no target or breakpoint policy. |
| Fluent menus | `MenuButton` and `SplitButton` expose `expanded` and click responses; the app owns the menu. | v9 composes `Menu` around the trigger. |
| Fluent choice colors | `Checkbox`, `Radio` and `Switch` change indicator colors without the CSS `transition`; only the `Switch` thumb eases (`durationNormal`, `curveEasyEase`). | Colors follow the state in one pass, as the buttons do. |
| Fluent `Slider` focus | The focus ring grows the root by `outlineOffset` (4 across, 2 along) outward, the vertical slider narrows it across; step ticks are 1pt bars ending at each step. | `createFocusOutlineStyle` offsets are not vendored. |
| Fluent text fields | The focus underline is a straight 2pt band scaling from the center (the CSS pseudo-element curves up at the corners); the `filled-*-shadow` appearances are not offered; the selection color is `colorCompoundBrandStroke` at 40%. | egui paints no clipped border; shadows belong to combobox surfaces; Fluent uses the browser selection color. |
| Fluent `Input` width | An unconstrained field is 200pt wide and a constrained one fills the constraint. | A browser `<input>` width is intrinsic (20 characters). |
| Fluent `Textarea` | `resize` is not offered; the height follows `rows` (default 2) between the size's `minHeight` and `maxHeight`, then scrolls. | egui has no resize handle. |
| Fluent `SpinButton` | The step buttons do not repeat while held; Home and End move the caret; `displayValue` is not offered; Large is Medium. Additions: opt-in mouse scrub (`scrub(ScrubRate)`), `select_on_step`, and the `clamped` output. | One step per press, the number format comes from the locale. |
| Fluent `RangeSlider`, `Rating` | `RangeSlider` binds `&mut [N; 2]` (any `Numeric`, as Material `ValueSlider::range`), each thumb is a focus stop with its own node; `Rating` is one slider node, not a radio group, and hover previews its value. | Core `RangeModel::drive` and the material `Rating` pattern. |
| Fluent `InfoLabel` | The info popover is drawn by the label (`overlay::Popup` above the button, `shadow16` surface, 264pt wide) until a `Popover` exists. | No Fluent `Popover` component yet. |
| Fluent `Select` | The field is drawn like `Dropdown` and opens the Fluent listbox; no native `<select>` popup. | egui has no native select. |
| Fluent `Dropdown`, `Combobox` | The clear button is not offered; typeahead on a closed `Dropdown` opens the list; `Combobox` hides options that miss the typed text (`filter(false)` turns it off, `freeform` keeps unmatched text); the listbox is a popup under the field (`overlay::Popup`, 2pt gap, field width, 160pt minimum), the active row is the active descendant, not focus. | Core `combobox` model and filter; v9 filters in the app. |
| Fluent `Dropdown` selection | Options carry app values (`item(value, option)`, `group(OptionGroup)`); `Dropdown`/`Combobox` bind `&mut K` (`new`), `&mut Option<K>` (`optional`) or a core `Selection<K>` (`multi`), `Select` one of the first two; `multiselect` follows the binding and keeps the list open. | v9 passes `selectedOptions` arrays of strings. |
| Fluent `TimePicker` | Times are listed with the locale format; free text parses ASCII `h`, `h:mm` and `am`/`pm` only and applies on blur or Enter; no error type is reported. | The core has no time parser. |
| Fluent `TagPicker` | Tags and the input wrap as one sequence (React lays the group and the input out as two flex items); tags follow list order, not selection order (`Selection` is ordered by key); selected options leave the list instead of the app filtering them; tag sizes follow the control size (medium: extra-small, large: small, extra-large: medium), derived from the control `minHeight` because `tagPicker2Tag` is not vendored; tags are not focus stops, Backspace in the empty input removes the last one. | `Selection<String>` is a sorted set and tags need no roving focus to be removable. |
| Fluent `Calendar` | Always six week rows; week numbers are ISO weeks; the month and year pickers keep the day view's height; the "go to today" button navigates without selecting; month and year items use roving focus (one Tab stop). | The core `MonthGrid` is a fixed 42-day grid and `date` has no locale week-number rule. |
| Fluent `DatePicker` | Typed text parses with the locale date order (`LocaleFormat::parse_date`) on blur or Enter and is on by default (`allow_text_input`); the calendar opens on a click in the field and does not take focus while text input is allowed. | The core date model parses numeric dates only. |
| Fluent `SwatchPicker` | Binds `&mut K` (`new`) or `&mut Option<K>` (`optional`) over `item(value, swatch)` entries; `EmptySwatch` is not offered; arrow keys move the selection (single Tab stop, as `RadioGroup`); `ImageSwatch` needs an egui image loader. | Core `RovingFocus`. |
| Fluent `ColorPicker` | Binds an `egui::ecolor::Hsva`; the area gradient is a mesh with square corners, the alpha checker is 8pt gray cells (the styles load an image); sliders are horizontal and 300pt wide, no `ColorSlider` saturation or value channels; one node per part, no inputs. | egui has no clipped gradients; the transparency image is not vendored. |

| Fluent `ProgressBar` | The indeterminate sweep (3 s linear, `-33%` to `100%`) is not in the vendored styles file (`ProgressBarIndeterminateMotion`); with reduced motion the bar is static full width; the rounded fill is not clipped by the track. | The motion file is not vendored; egui has no rounded clipping. |
| Fluent `Spinner` | With reduced motion the arc is static (React keeps a slow 1.8 s rotation and a gradient tail); the tail is built from the `::before` and `::after` arcs as butt-capped strokes. | Core reduced motion is the end state, as `LoadingIndicator`. |
| Fluent `Skeleton`, `SkeletonItem` | `Skeleton` hands a `SkeletonContext` to its closure instead of React context; `size` snaps to the nearest styled size; the wave band is clipped to the item's rect, so circle corners show it; no `row` or `aria-busy`. | egui has no clipping to a rounded shape. |
| Fluent `MessageBar` | `layout` has no `auto` reflow (singleline truncates, multiline wraps); actions are an app closure (`show_with`), dismiss is a transparent icon button; `MessageBarGroup` is a plain column with no enter or exit animation (no styles in the vendored file). | Reflow measures arbitrary children; the group has no vendored motion. |
| Fluent `Toast`, `Toaster` | Toasts queue in a core `ToastQueue<Toast>` (`toast_queue`: 20 visible, 3 s); `pause_on_hover` is off by default as in React; position is per toast; actions are `ToastLink`s paired with a value of the queue's type (`Toast<A>::action(value, link)`), reported by `ToasterResponse::action_clicked` (the toast id and the value), not arbitrary children; the 16pt edge offset, 16pt gap and 300 ms fade and slide are not in the vendored styles files (`getPositionStyles`, motion). | Core `ToastQueue` and the snackbar host pattern. |
| Fluent `Badge`, `CounterBadge`, `PresenceBadge` | Badges live in `feedback`, not `data`; `Badge` takes text and an optional icon, no custom slots; the presence glyphs are drawn as shapes (disc, ring, check, clock hands, bar, arrow, cross, slash, question mark), not the react-icons SVGs; presence has no `size` of its own, it reuses `BadgeSize`. | The presence icons are not in the icon font. |
| Fluent `Tooltip` | Escape hides it until the pointer leaves and returns; no enter or exit motion; hover and focus on the trigger drive it, the tooltip itself is not hoverable. | The tooltip presence motion is not ported. |
| Fluent `Popover` | The surface is always its own overlay layer, so `inline` has no effect and is not offered; `openOnHover` and `openOnContext` are not offered (clicks toggle it); `trapFocus` cycles Tab through two zero-size sentinels, the surface itself is not a tab stop. | egui layers cannot nest in the trigger's layout; core has no focus trap. |
| Fluent `TeachingPopover` | One `TeachingStep` list replaces the `TeachingPopoverCarousel` parts; the footer shows nav dots and previous and next buttons, no page count; the brand footer buttons keep the primary and secondary button appearances (React inverts them); the surface is 288pt of content between 16pt padding, the body media slot is not offered. | The carousel card and nav styles need `Carousel` context that egui lacks. |
| Fluent `Dialog` | The surface is always `maxWidth` (600pt, the screen width up to the 480pt breakpoint) instead of fitting its content; the 0.85 scale of `DialogSurfaceMotion` is not applied, it fades only (the backdrop shares the surface curve instead of `curveEasyEase`); `fluid` actions share the surface width equally; actions up to the breakpoint stack as a column; `alert` ignores Escape and backdrop presses; `non-modal` closes on Escape only and does not trap focus. | egui areas cannot scale; `DialogActions` fluid styles are not in the vendored files. |
| Fluent `Drawer` | One `Drawer` has `show_modal` and `show`; sizes are fixed points clamped to the screen or the available space; the slide uses the `drawerMotions.ts` durations and curves without the opacity and `shadow64` transitions; the body scrolls between header and footer, whose heights lag one pass; `separator` is an inline drawer option, the header and footer scroll separators are not drawn. | egui `Panel`s dock only to a container edge. |
| Fluent `Card` | `CardHeader`, `CardPreview` and `CardFooter` are `CardUi` methods; the header takes a title, description and icon image instead of slots; the preview is not clipped to the rounded corners; the horizontal card centers its parts only after its height is known (one pass); the selectable card has no `floatingAction` slot, `checkbox(true)` shows the checkbox. | egui has no clipping to rounded rects or slot composition. |
| Fluent `Accordion` | `multiple` is the `Expansion` mode, the open items are an `Expansion<K>` of the keys passed to `AccordionUi::item(key, ..)`; `navigation` is off unless set; the panel collapse animates the height and opacity with `curveEasyEaseMax` over `durationNormal` but no whitespace atom; a locked last open item stays clickable and does nothing. | Core `Expansion` owns the open set; egui layout has no margin collapse. |
| Fluent `Image` | `fit` modes apply inside an explicit `size`, without one the box is the natural size (React fills the parent); `block` scales the height by the aspect ratio; `alt` absent means no semantic node. | egui has no parent-relative `100%` sizing. |
| Fluent `List` | Items are the `ListUi::item` closures with a label, keyed by `ListUi::item(key, ..)` into a core `Selection<K>`; both navigation modes use one roving tab stop and Up, Down, Home and End; `composite` only changes the role to `grid`; items align to the top of their row. | Core `RovingFocus` and `Selection`; no cell-level grid navigation. |
| Fluent `TabList` | The selection indicator slides by interpolating its span between tabs (`durationSlow`, `curveDecelerateMax`) instead of a transform from the previous tab, inset included; tabs do not scroll or wrap, overflow is the `Overflow` component. | CSS transform animation is not available; v9 tabs never wrap. |
| Fluent `Toolbar` | Items are builder calls (`action`, `toggle`, `radio_group` with `option`, `divider`, `group`; named so they read apart from egui `Ui::button`) instead of child components, radio buttons share one bound value (`ToolbarRadioGroup::new(&mut T).item(value, button)`) instead of `checkedValues`, the clicked button is `ToolbarResponse::clicked` with its value (toggles and radio buttons report through `changed`), `ToolbarGroup` adds no semantic node; arrow keys follow the toolbar axis only (tabster `axis: both` also accepts the cross axis); buttons in a vertical toolbar keep the row layout (no column `ToolbarButton` with a 24pt icon); the vertical divider rule spans the toolbar width minus its padding. | Core `RovingFocus` is per axis; `PushButton` has no stacked layout. |
| Fluent `Breadcrumb` | `BreadcrumbItem` wraps a `BreadcrumbButton` and dividers are inserted between items by `Breadcrumb` (one glyph via `BreadcrumbDivider`), no `<ol>` list node or `aria-current`: the current item is reported as disabled and ignores clicks; there is no `href` anchor form, apps navigate from `BreadcrumbResponse::clicked`; no icon-only item; overflow is the `Overflow` component. | Core semantics have no current state; links are app routing. |
| Fluent `Overflow` | A size-fitting function (`Overflow::fit`) over measured item widths plus the `Overflow` option set on `Toolbar::overflow` and `Breadcrumb::overflow`, not a container with `OverflowItem` children and `useOverflowMenu`; one axis (horizontal), no `groupId` or `overflowAxis`; the hidden items are rows of a `Menu` behind a trailing `...` button (a `Breadcrumb` with `OverflowDirection::Start` shows it before the trail), toggles and radio buttons stay checkable rows; item widths are the natural widths one pass ahead; a vertical `Toolbar` does not overflow. | egui has no layout-time child measurement or `ResizeObserver`. |
| Fluent `Nav` | `NavDrawer` is an inline panel on the start edge (260pt, `colorNeutralBackground4`), not an `InlineDrawer` or `OverlayDrawer`: no open state, motion, `NavDrawerHeader`, `NavDrawerFooter`, `Hamburger`, `AppItem` or `SplitNavItem`; selection and open categories are app values (`Option<K>`, `default_open`, `K: ItemKey`) instead of strings, and a row without `salt(..)` is keyed by its value; rows are `NavUi` methods (`item`, `category`, `sub_item`, `section_header`, `divider`), a closed category runs no `add` closure and learns its sub items' values when first opened (the selection indicator needs one open pass); the selection indicator and icon swap appear at once instead of fading over `durationFaster`, the category chevron flips instead of rotating, the sub item group has no collapse motion; rows are links without `href`, selection is reported through `selected` (no `aria-current`). | Core semantics have no current state; egui has no presence motion. |
| Fixed corner radii | The checkbox box (`RadiusSize`, 2dp) and the primary tab indicator (3dp), fixed in Compose, scale with `Shape::extra_small` over its 4dp default, so the default theme paints the spec and a sharper or rounder scale carries them along. | Theme shape scales reach every corner. |
| `Menu` toggles | `MenuItem::check` and `MenuItem::radio` (`menuitemcheckbox`, `menuitemradio`) put a check or a 10dp dot in a toggle column that a menu level reserves once one item has a toggle, before the leading icon; MD3 menus only mark `selected` items (expressive: a leading check that a leading icon replaces). | Desktop menus show a state and an icon on one entry. |
| Fluent `Menu` | `Menu::show` takes the trigger response and an `open` flag like `Popover`; rows are `MenuUi` methods (`item`, `checkbox_item`, `radio_item`, `group`, `divider`, `submenu`) instead of components, checked state is a `&mut bool` or a `&mut T` group value, not `checkedValues`; `MenuSplitGroup`, `openOnHover`, `openOnContext`, the safe zone and surface motion are not offered; typeahead is `useMenuList`'s single character jump (next enabled row, wrapping, case-insensitive, no multi-character prefix); a submenu opens by click, the forward arrow or `hoverDelay`, and hovering another row closes it after `hoverDelay`; `Menu::radio_dot` marks a checked radio with the `Radio` dot instead of the checkmark. | Core `Popup` has no nested-popup dismissal; rows are immediate-mode. |
| Fluent item ids | Collection items (`ListOption`, `RadioOption`, `Swatch`, `AccordionItem`, `ListItem`, `DialogAction`, `Tab`, `MenuItem`) take `.salt(..)` for a stable egui id and agent key (default the item's value, actions their index); `ListUi::item` takes a `ListItem` instead of a label and flag. Selection groups bind item values (`SelectionResponse<K>::selected`); lists, accordions and tables key selection and open state by app keys (`Selection<K>`, `Expansion<K>`, `table::Rows<K>`), so both follow items through inserts; items default their ids and agent keys to the value, as in Material. | Core `Selection` and `Expansion` are keyed by the app's type; Material's item salt has the same scope. |
| Fluent `Tree` | `Tree` renders a `TreeData` model (`Tree::items` over `TreeItem`, `TreeItem::from_levels` for `FlatTree` data) with `Expansion` and a `BTreeSet` of checked keys instead of `openItems` and `checkedItems` maps; `TreeItem` has no `itemType` prop (children make a branch) and no `onOpenChange` or `onCheckedChange` (read `TreeResponse`); `TreeItemLayout` and `TreeItemPersonaLayout` are `ItemLayout` values with `iconBefore`, `iconAfter`, `aside`, `media` and `description` only: no `actions` slot, `media` is an `Avatar` painted at 32 inside the row (not a nested widget, so it has no semantic node of its own) and no `TreeItemChevron` rotation (the open chevron is the down glyph); no collapse motion, `Tree` nesting inside `TreeItem`, `navigationMode`, `treeitem` `aria-setsize` or `aria-posinset`, `Space` toggles the check only with a selection mode, `Enter` and clicks activate and toggle branches; rows are laid out flat, the subtree `paddingTop` is the uniform `rowGap`. | Core `TreeData` and `tree::on_key` own the keyboard model; no Avatar component, no presence motion. |
| Fluent `MenuGrid` | `MenuGrid::show` takes the trigger response and an `open` flag like `Menu` and draws the `MenuPopover` surface itself (no `Menu`, `MenuTrigger` or `MenuPopover` around it, no inline form, as upstream); rows are always the 290pt `MenuGridRow` `maxWidth` wide (the popover is not `max-content`); Tab closes it and returns focus to the trigger; no `MenuGridGroup`, `MenuGridGroupHeader` or nested menus; a row is a `MenuGridRow` value of `MenuGridCell`s (`MenuGridItem` with icon, label and sub text, `MenuGridAction` as the icon-button cell) instead of arbitrary children; `firstSubAction` and `secondSubAction` are `MenuGridAction` cells, an item is a cell of its own (not the row), so Enter and clicks activate the cell and the row has no own activation; arrows move across cells and rows with the core `on_grid_key` (no wrapping, a shorter row clamps the column, disabled cells are skipped by repeating the step), no type-ahead; the row hover fill follows the pointer over the row, focus rings the focused cell. | Core grid navigation has no row-level focus; `Menu` rows here are `MenuUi` rows, so the grid owns its popover. |
| Fluent `Carousel` | `Carousel::show` takes cards as closures (`CarouselUi::card(key, ..)`) and runs only the active one; the active card is an app key (`&mut K`, snapped to the first card when no card carries it) instead of `activeIndex`; there is no `CarouselSlider`/`CarouselViewport` scroll (no drag, swipe, scroll snap or slide motion, `autoSize`, `align`, `groupSize` or `whichCardIsActive` events), no `CarouselNavImageButton`, `overlay` or `inline-wide` `CarouselNavContainer` layouts (the inline layout only) and no `onActiveIndexChange` (read `CarouselResponse::selected`); the elevated appearance paints the shadow and rounding for the card box without clipping its content; the dots are tabs with roving arrows that select on focus; buttons are `PushButton`s (subtle, circular) named by the catalog (`mineral-carousel-*`, React leaves `aria-label` to the app) unless `previous_label`, `next_label` or `autoplay_label` is set; autoplay is opt-in with an interval, starts paused, and stays off while reduced motion is on. | Core has no scroll-snap carousel model. |
| Fluent `MenuSplitGroup` | `MenuUi::split_item` takes the main `MenuItem` and the submenu content: the group is one call, not a `MenuSplitGroup` wrapping two `MenuItem`s, so the trigger has no label, icon or `persistOnClick` of its own and shows only the submenu indicator; the trigger separator height is the group's 20pt (`MenuItem`'s own `splitItemTrigger` says 24pt), the main part keeps its full rounding as the group styles leave it, multiline items are not aligned (`data-multiline`); the trigger is reached from the main part by the start-to-end arrow and is not in the vertical arrow order of its own (Up and Down from it step to the neighbouring rows), type-ahead matches the main label only. | Core focus has no nested item model; MenuUi rows are the only Menu content here. |
| Fluent `Avatar` | No `badge`/`image`/`initials`/`icon` slot props: `presence` takes a `PresenceBadge` status, `image` an egui `ImageSource` (cover fit, drawn over the initials once loaded), `initials` a string, `icon` a `FluentIcon`; the badge cutout is a `colorNeutralBackground1` disc under the badge (CSS `mask-image` has no egui equivalent), the active ring and shadow paint outside the box without layout space, and `active`/`inactive` switch without the scale and opacity transitions. | egui has no masks or CSS transitions. |
| Fluent `AvatarGroup` | `AvatarGroup::item` takes `Avatar`s (no `AvatarGroupItem` slots, the overflow row shows the avatar and its name); the `pie` layout paints each slice clipped to a rect and filled as the circle polygon, images in slices are clipped to the rect only; no overflow `Tooltip` (the trigger's accessible name is its text) and the popover keeps `Popover` `small` padding (12) instead of `spacingVerticalS`/`spacingHorizontalS`; `AvatarGroupPopover` `indicator` follows the size rule only. | egui has no `clip-path`. |
| Fluent `Persona` | `Persona` paints its grid itself (no `Avatar`/`PresenceBadge` child widgets, so the avatar has no semantic node of its own: the persona is one `Group` named by its text lines); `avatar` takes an `Avatar` whose size the persona overrides, `presence` forwards a status (badge slot of the avatar, or the media with `presence_only`); the text lines never wrap or truncate. | egui has no CSS grid. |
| Fluent `Tag`, `InteractionTag`, `TagGroup` | `Tag::new` takes a `value` (id salt) and the label; `media` takes an `Avatar` and `icon` a `FluentIcon`, no free slots; `TagGroup` takes its tags as entries with an app key (`tag(key, ..)`, `interaction_tag(key, ..)`) and a `Selection<K>` instead of `selectedValues`/`onTagSelect`, `TagGroupResponse::removed` is the key, selection applies to `InteractionTag` primaries only (a `Tag`'s `selected` is the look); `dismissible` on `InteractionTag` adds the secondary button (no `InteractionTagSecondary` slots or custom icons); roving focus runs along the row only (`axis: 'both'` has no second dimension in one row), the `role` prop is fixed to `toolbar`, and no WCAG hit-area extension of `extra-small`. | egui has no slots or DOM roles; one row has one axis. |
| Fluent `Table`, `DataGrid` | `Table::show` draws a header row from `TableColumn`s (`TableHeaderCell`: label, sortable, width) and body rows from a cell closure, so `TableHeader`, `TableRow`, `TableCell` and `TableSelectionCell` are not public types; sorting is a core `SortState` bound with `sort` and a per-cell `sort_by_key` in place of `useTableSort`'s column `compare` functions, selection is a `Selection<K>` of the row keys given to `show(ui, rows, ..)` (`table::Rows<K>`: `usize` data indices, a key slice or `RowKeys`) (a checkbox column, circular for a single selection instead of a `radio`) with click, Ctrl/Shift handling from `Selection::click`; resizing is a core `ColumnWidths` and the handle is the 16pt drag zone without upstream's keyboard resize; a `DataGrid` is one Tab stop whose selection cells are the checkboxes themselves (roving cells, not a `gridcell` around an indicator); only rows crossing the clip rect are drawn (plus the row of the Tab stop), so arrow keys focus a hidden row one pass later, after scrolling to it, and hidden rows have no semantic nodes; the row hover and pressed fills follow the pointer over the row, cell text keeps its own color (no row `color` inheritance); cells have no `TableCellActions`, `subtle`/`hidden` selection cells or `TableCellLayout` truncation. Additions: `row_style` tints unselected rows, `TableResponse::rows` hands each shown row its response (non-grid rows sense clicks without focus, for context menus). | Core `table`/`select`/`focus` models own sort, selection and grid keys; no DOM table layout. |
| Icon sets (both kits) | Material Symbols (`IconSet::material`) and Fluent UI System Icons (`IconSet::fluent`) are the defaults of their kits; `from_icon_fonts(..).with_icons(..)` of both kits take any `IconSet` and icon fonts, so a Fluent app can draw its chevrons, dismiss and checkmarks from Material Symbols and the reverse. Such a mix is an app choice that departs from the respective spec (glyph shapes, metrics and the filled/regular pairing follow the font used, which for fonts without a second form repeats the glyph via `Icon::single`); the kits do not check that a font covers the role glyphs. |
| Fluent `extras` (`SplitPane`, `CommandPalette`, `MenuBar`, `StatusBar`, `Pagination`) | Not Fluent UI React v9 components: they port the Material `extras` of the same name onto Fluent tokens and parts (catalog `Origin::Other`, `Category::Extras`, no vendored styles file). | Fluent `MenuBar` | Takes `BarMenu`s (title, mnemonic, `FnOnce(&mut MenuUi)` rows) instead of prebuilt menus, so a row click is `MenuBarResponse::clicked` (the row's value), not a path on the response; titles are subtle `PushButton`s (role Button, key `<id_salt>-<i>-menubar-item`), the open one `Secondary`. | Fluent `Menu` is closure-driven and anchored to a trigger. Escape closing the menu returns focus to a title in the Material strip, unverified here. |
| Fluent `FormGrid` | Extras component, no React v9 counterpart: horizontal `Field`s share a label column as wide as the widest label (at most half the width; longer labels wrap), `subtitle2` section headings, full-width rows. | Desktop settings and property forms align their controls; Fluent leaves it to CSS grid. |
| Fluent `StatusBar` | Core `StatusProgress::Circular(_)` shows the extra tiny `Spinner` and ignores its fraction (Fluent has no circular determinate indicator), `Linear(Option<f32>)` the 48dp `ProgressBar`. Colors: `colorNeutralBackground3` strip, red palette error tone. | Fluent progress parts. |
| Fluent `Pagination` | Page buttons are checked `ToggleButton`s (state `checked`, not `selected`) 28dp wide, below the button minimum width, named by the page number; first/last use the media previous/next glyphs. | Fluent has no selected-button state; pages are one to three digits. |
| Fluent `CommandPalette` | Rows are painted like the `Combobox` `Option` (no check slot), hits in semibold; no virtual list (a plain scroll area); the item salt defaults to the index only. | Palettes hold tens of commands. |
| `ValueSlider::min_icon`, `max_icon` | The track icons are named after the value end they sit at, not `icon`/`trailing_icon`. | `trailing_icon(icon, label)` is an icon button everywhere else; the slider icons are decorative and follow the value direction on a vertical or reversed track. |
| Picker and search labels | `DatePicker::new`, `DateRangePicker::new`, `TimePicker::new`, `SearchBar::new`, `SearchSuggestions::new` and `SearchView::new` take a label: the accessible name of the picker dialog (and the docked date field label) or of the search field. | `SideSheet::width`, `Card::width`, `SearchView::width` | Take bounds (`impl Into<Rangef>`) like `Dialog::width`; equal bounds fix the width. A side sheet is 360dp clamped into them. | One meaning of `width` across containers; a second `width_range` setter is gone. |
| `RichTooltip` actions | Any number of `TextAction`s, reported by index in `RichTooltipResponse::clicked`, instead of Compose's single `action` slot. | Same shape as `Alert` and `Dialog` actions. |
| Fluent prop names | `secondary_text` replaces `subText` (`MenuGridItem`), `secondaryContent` (`MenuItem`), `subtitle` (`Toast`) and `description` (`TableCellLayout`, `TreeItem`, `CardHeader`); `icon_before`/`icon_after` replace `contentBefore`/`contentAfter` and take icons only; `axis(Axis)` replaces `vertical` (`Toolbar`, `TabList`) and `orientation` (`Field`, `Card`). | One name per concept across components ([conventions](conventions.md)); the core `Axis` is the orientation vocabulary. |
| Fluent typed actions | `Dialog::action`, `Drawer::footer_action`, `MenuUi::item`/`split_item`, `MenuGridRow::cell`, `Toolbar::action`, `Breadcrumb::item` and `Toast::action` pair each item with an app value; `DialogResponse`, `DrawerResponse`, `MenuResponse` (returned by `Menu::show` in place of `OverlayResponse`), `MenuBarResponse`, `MenuGridResponse`, `MenuGridRowResponse`, `ToolbarResponse`, `BreadcrumbResponse` and `ToastAction` report it as `clicked: Option<A>`. | Fluent value binding | `TabList`, `ToolbarRadioGroup`, `SwatchPicker`, `RadioGroup`, `Nav`, `Dropdown`, `Select` and `Combobox` items carry an app value (`item(value, x)`) and the group binds `&mut K` (`new`), `&mut Option<K>` (`optional`) or `&mut Selection<K>` (`multi`); nothing is selected while the value matches no item. | v9 `value`/`selectedValue` props are strings or `unknown`; a typed value needs no lookup table in the app. |
| Fluent control validation | `Input`, `Textarea`, `SpinButton`, `Select`, `Dropdown`, `Combobox`, `TagPicker`, `DatePicker` and `TimePicker` take `validation(Option<Validation>)` instead of `aria-invalid`; only `Validation::Error` changes the control (red border, invalid state), warning and success show in the `Field` message. | `FieldContext::validation` forwards in one call and the controls can style the other states later without an API break. |
| Fluent `Dialog::show_modal` | The one show method is `show_modal`, also for `DialogKind::NonModal` (no backdrop, no focus trap). | Material naming of modal surfaces; `modalType` stays an option of the one dialog. |
| Fluent `Tree` selection | `Tree::selection` binds a core `Selection<Key>`: its mode picks radio (`Single`) or checkbox (`Multiple`) selectors, no call shows none. | v9 passes `selectionMode` and `checkedItems`; `List`, `Table` and `TagGroup` bind a `Selection` too. |
| Fluent `TagPicker::control` | `TagPickerControl::{Input, Button}` picks the control next to the tags. | v9 composes `TagPickerInput` or `TagPickerButton` as children. |
| Fluent high contrast switch | `Fluent::set_contrast_mode(ContrastMode)` switches the scheme; v9 apps swap the theme object. | The brightness is the runtime's, high contrast is the kit's own axis. |
| Fluent dp setters | `TableColumn::width`, `Field::label_width`, `NavDrawer::width` and `Overflow::padding` take points and sanitize them (`kit::sanitize::at_least`). | Extents of container parts and layout rules, which have no `Constraints` for `SizeExt` to narrow. |
| Fluent `StatusBar` elision | An item with `StatusItem::elide(..)` always cuts its end; `Elide::Middle` and `Elide::Start` act as `End`. | Not in v9; the text is painted from one truncating egui layout job. |
